# 委員会メールの扱い

統合アプリの「メール」の画面（`SMM_AUTH_MODE=discord` のとき）に、委員会のメールをどう載せ、誰が何をできるかをまとめます。
合成データ版（`demo`・`trusted-proxy`・`account` の各モード）の受信箱は、受信箱ごとの閲覧の許可で動く別の規則です（[`app/docs/requirements.md`](../app/docs/requirements.md)）。

実装は `app/src/server/mailbox/`。

## 1. 方針

| 項目 | 内容 |
|---|---|
| 集める元 | 委員会の共用の Google Workspace アカウント。委員会のすべてのグループのメンバーにしておく |
| 載せるアドレス | 委員会のアドレス（グループのアドレスと共用アカウント）。個人名のアドレスは載せない |
| 取り込む範囲 | すべてのメール。過去の分は、別のアカウントから 1 回だけ送り込める |
| 伏せ字・除外 | 取り込みでは除外しない。確認コードなどの認証メールは、権限の管理者にだけ中を見せる（§4） |
| メールの画面のログイン | その端末でメールを最後に使ってから一定の時間（設定 `idleHours`、例では 12 時間）を過ぎたら、メールの画面だけパスワードを入れ直す。ほかの画面のログインは 14 日のまま |

「使った」とは、メールの一覧・本文・添付を開いたこと、または対応の情報・メモを変えたことです。ホームの未対応の件数は数えません。
この方式で弱くなる点：端末を拾った人が時間内に使い続けると、ログインの期限まで読めます。そのときは設定の画面の「すべての端末からログアウト」を使います。

## 2. 載せる・載せないの判定

委員会のアドレスかどうかは、運用者の設定ファイル（`SMM_MAIL_CONFIG`、形は [`app/deploy/unified/mailbox.example.json`](../app/deploy/unified/mailbox.example.json)）の `mailboxes` に載っているかで決めます。
アドレスは小文字にそろえ、`domainAliases` で別名のドメインを本来のドメインに直し、委員会のドメインでは `+` 以降を外します（`info+managers@` は `info@`）。

| 取り込み元 | メール | 扱い |
|---|---|---|
| 共用アカウント（新着） | To・Cc・差出人・List-Id（グループ経由の印）・件名の先頭のグループの印のどれかに委員会のアドレスがある | そのアドレスの受信箱すべてに載せる |
| 共用アカウント（新着） | どれにも委員会のアドレスがない（共用アカウントへの Bcc など） | 共用アカウントの受信箱（`catchAll`）に載せる |
| 過去の分の送り込み | To・Cc・差出人に委員会のアドレスがある | 載せる |
| 過去の分の送り込み | グループ経由で届いた（List-Id か、件名の先頭のグループの印） | 載せる（`backfillUseGroupDelivery: false` で止められる） |
| 過去の分の送り込み | 個人名のアドレスだけで、グループ経由の印もない | 載せない（GAS が送らず、アプリも保存しない） |

- **グループの中のグループ**：グループが別のグループに転送しているときは、転送先の受信箱すべてにも載せます。関係は `forwardsTo` に書きます。転送先の先もたどります。
- **件名の印**：Google グループの「件名の接頭辞」（例 `[adm]`）は、通ったグループを示すので手がかりにします。`Re:` の後ろに残った古い印は数えません。印と受信箱の対応は `subjectTag` に書きます。
- `Delivered-To` は共用アカウント自身を指すだけなので、これだけでは受信箱を決めません。

## 3. 見られる人とできること

- **読む**：委員会の Discord サーバーにいま参加している人（Bot を除く）。部署や権限で制限しません。試しに一部の人だけに出すときは、`previewDiscordUserIds` に載せた人だけがメールの画面を開けます。
- **ラベル・担当者・対応状況の変更**：ログインしている委員全員。対応状況は、1 通ずつのほか、スレッドの全メールをまとめて変えられます（`PATCH /api/threads/:threadId/status`。変わったメールごとに履歴を残す）。
- **内部メモの追加**：メールが載っている受信箱のどれかで、権限の管理者が編集の権限を付けた人だけ。対応の情報は 1 通に 1 つで、載っている受信箱すべてで共通です。
- **送信・返信**：受信箱ごとに権限の管理者が付けた送信の権限を持つ人が、その受信箱のアドレスを差出人にして、新しいメール・返信・全員に返信を送れます（添付も可）。差出人にできるのは、設定の `send.mailboxes` にあるアドレス（共用アカウントの Gmail に差出人として登録したもの）だけです。送ったメールは記録用のアドレス（`draftBccAddress`）にも Bcc で届き、スレッドに「完了」として載ります。
- **削除**：アプリからはしません。

送信の設定（`mailbox.json` の `send`）：

| キー | 内容 |
|---|---|
| `smtpHost`・`smtpPort` | 送信に使う SMTP（ポートは 465 か 587） |
| `smtpUser` | 共用アカウントのアドレス |
| `smtpPasswordFile` | 共用アカウントのアプリパスワードを書いたファイル。所有者だけが読める権限（0600）にする |
| `fromName` | 差出人の名前 |
| `mailboxes` | 差出人にできる受信箱の `id` |
| `maxAttachmentMB`・`maxRecipients` | 添付の大きさと宛先の数の上限 |

`send` が無ければ、メールの画面は読むだけになります。

## 4. 表示と個人情報

- 本文・添付・宛先（To・Cc）は、メールに書かれたとおりに見せます。Bcc は保存しません。
- 守っていること：
  - HTML は安全にしてから（スクリプト・フォーム・イベントを取り除く）、隔離した枠でだけ表示する。外部の画像は読み込まない（相手に開封を知らせない）。
  - 添付はダウンロードだけ。アプリの画面の中では開かない。
  - サーバーのログに本文・宛先を書かない。取り込みに失敗したときも、内容は記録しない。
  - 統合アプリのメールは、Bot の `/ask` の検索や索引に流さない。Bot のデータソースに渡すのは件名・差出人の表示名・対応状況だけ（[contracts/bot-datasource.md](contracts/bot-datasource.md)）。
- 認証メール：パスワードの再設定・確認コード・ログイン通知などは、件名・本文・添付を権限の管理者にだけ見せます。ほかの委員には差出人と「（認証メールのため非表示）」だけが出て、検索も中を見ません（推測したコードで当たりを探せない）。対応状況・ラベル・担当者は委員全員が変えられるので、権限の管理者へ回せます。Bot のデータソースでは、誰に対しても件名を伏せます。
  - 見分け方：件名の形、本文の「コードの名前の近くの 4〜8 桁」、設定 `restrictedSenderDomains` に書いた差出人のドメイン（サブドメインを含む。既定は空）。実装は `app/src/server/mailbox/restricted.ts`。
  - 判定は保存せず、読むたびに行います。規則や差出人の一覧を変えると、過去のメールにも効きます。
  - 見分けは件名と本文の形によるので、漏れも誤りもあり得ます。差出人で丸ごと伏せたいときは `restrictedSenderDomains` に書きます。

## 5. 取り込みの経路

- GAS（[`app/deploy/unified/gas/send_mail_to_app.gs`](../app/deploy/unified/gas/send_mail_to_app.gs)）が、Gmail の元のメール（RFC 5322）を 1 通ずつ `POST /v1/mail/ingest` へ送ります。署名は `svc-auth/v1`、クライアント ID は `mail-collector` で、本文のバイト列の SHA-256 を署名に含めます。
- 鍵は、サーバーの鍵のファイル（設定の `ingestKeyFile`）と GAS のスクリプト プロパティにだけ置きます。
- 同じ Message-ID のメールは 1 通として保存し、当てはまる受信箱すべてにつなぎます。最初に届いた写しの内容を残します。
- 取り込みでは Gmail に何も書き込みません（移動・削除・既読にする機能がない）。送信だけは SMTP で別に行います。

GAS の設置のしかたは [deployment.md](deployment.md) §6。

資料の検索のために Gmail を JSONL として保存する GAS（[`gas/mail/collect_mail.gs`](../gas/mail/collect_mail.gs)）は、これとは別のものです。

## 6. 保存

- SQLite（`SMM_MAIL_DIR/mail.sqlite3`）と、添付のファイル（内容の SHA-256 ごとに 1 つ、`attachments/`）。
- 統合アプリの日々のバックアップに含めます（[deployment.md](deployment.md) §5）。
- 保存の期間は運用者が決めます。元のメールは Gmail に残ります。

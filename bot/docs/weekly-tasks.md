# 週1回のタスク一覧と、未割当タスクの追い投稿

Discord の Bot が、週に1回（既定は月曜 8:40）タスクの一覧を投稿します。見た人が担当の人に催促し、未割当のタスクは「引き受ける」ボタンで決められます。投稿の中身・順序は `src/iyakusai_bot/weekly_logic.py`・`weekly_service.py` にあり、Discord の口は `weekly_cog.py` にあります。

## 何ができるか

- **週1回の一覧**: 部局ごとに、進行中・期限切れ・今週が期限（今日から 6 日以内）のタスクを、担当の名前つきで出す。
- **未割当の上位**: 未完了で主担当の決まっていないタスクを、期限の近い順に上位 `candidate_limit` 件（既定 5 件）出す。各タスクに「引き受ける #番号」ボタン。押した人が主担当になる。
- **今週の決定・変更**: 統合アプリの決定の口（`sources: decisions`）が使えるときだけ節を出す。使えないとき（口が無い・401・404・そのほかの読み取りの失敗）は節を出さずに続ける。
- **追い投稿**: 一覧に載せた未割当のタスクが `follow_up_days` 日（既定 2 日）たっても未割当なら、同じ部局で担当の実績がある人を、持ちの少ない順に名前で添えて 1 回だけ投稿する。

## 使い方（委員）

- 一覧の「引き受ける #番号」を押す。押した人が主担当になり、結果は本人にだけ出る。
  - 成功すると、元の投稿のそのボタンは外れ、末尾に「✅ #番号 は ○○ が引き受けました。」の一行が付く（本文が長すぎるときは一行は付けず、ボタンだけ外す）。
- すでに担当が決まっていれば、その旨が本人にだけ出て、何も変わらない。同じ人がもう一度押したときは「すでにあなたが主担当です」と返す。
- 権限が無いとき（投稿先が見えない・サーバーの委員でない等）は、本人にだけ断りが出る。`/todo assign` と同じ確認を通る。
- 候補の人は、追い投稿の名前を見て `/todo assign` で担当を決めてもよい。
- 一覧は投稿時点の写し。完了や担当の変更は一覧に反映されない（最新は `/todo` の一覧で見る）。

## 有効にする方法（管理者）

1. `config.toml` の `[tasks]` を `enabled = true` にし、投稿先のチャンネルが `guild_ids`（`channel_ids` を使うならその中）に入っていることを確かめる。
2. **投稿先は、@everyone（サーバーの全員）から見えないチャンネルにする。** 委員だけが見えるチャンネルに置く。@everyone から見えるチャンネルだと、一覧と追い投稿は ERROR を残して止まる（タスクの名前や担当が委員以外にも見えるため）。委員だけのサーバーでも、全員が見えるチャンネルは使えない。
3. `[weekly]` を書く（例は `src/config.example.toml`）。最低限 `channel_id` が要る。
4. 決定・変更の節も出すなら `[kiban]` を有効にする（下の「決定・変更の節」）。
5. Bot を再起動する。ログに「週1回のタスク一覧を有効化」が出れば動いている。
   - 一覧の投稿先が使えないときは ERROR を残して、週1回の一覧ごと止まる（Bot は止まらない）。
   - 追い投稿の送り先が使えない・一覧と別のサーバーにあるときは、ERROR を残して追い投稿だけ止まる（一覧は続く）。追い投稿の送り先は、一覧と同じサーバーにある必要がある（タスクの読み取りが同じサーバーを見るため）。
   - 週の途中で有効にしたときは、その時刻をすでに過ぎていれば、その場で今週分が 1 回投稿される。
6. 送り先を一か所にまとめるなら `[notify]`（[notify-routing.md](notify-routing.md)）。一覧（`weekly_tasks`）と追い投稿（`weekly_follow_up`）は別の種類なので、別々に上書きできる。上書き先も、@everyone から見えないチャンネルにする。

止めるときは `enabled = false`（または `[weekly]` を消す）にして再起動する。止めた後も、過去の投稿の「引き受ける」ボタンは残るが、押すと「週1回のタスク一覧は現在停止中」と返す（`[tasks]` が有効なままのとき。`[tasks]` も止めたときは、ボタンは登録されないので、Discord で「インタラクションに失敗しました」と出ることがある）。

設定の項目:

| 項目 | 既定 | 内容 |
|---|---|---|
| `enabled` | `true`（節があるとき） | `false` で止める。節が無ければ何もしない |
| `channel_id` | （必須） | 投稿先。`[notify].channel_id` があればそちらへ送る |
| `weekday` | `1` | 1＝月曜 … 7＝日曜（ISO） |
| `time` | `"08:40"` | 日本時間の時刻（`HH:MM`） |
| `follow_up_days` | `2` | 未割当のまま何日で追い投稿するか（1〜14） |
| `mention_candidates` | `false` | `true` のときだけ、追い投稿で候補の人に通知を鳴らす |
| `candidate_limit` | `5` | 未割当の一覧に出す件数（1〜5） |

## 決定・変更の節（`[kiban]` と `sources` の注意）

- 節を出すには、`[kiban]` の `enabled = true`・`app_url`・`key_file` が要る。決定の取得は週1回の投稿のときだけ行い、`sources` の設定には依存しない（決定だけを要求する）。
- ただし `[kiban]` を有効にすると、統合アプリとの同期（`interval_sec` ごと）も動く。その既定の `sources` は `rental`（物品）と `mailbox`（受信箱）なので、それらの写しが `/ask` に入る（`/ask` の答えは Discord で全委員に見える）。物品・受信箱を入れたくないときは `sources = ["decisions"]` にする。
- `sources` に `decisions` を入れるのは、統合アプリが `decisions` に対応してから。対応前に入れると、その同期は 401 で失敗し続け、`kiban/_status.md` に失敗と出る。物品・受信箱の写しは `sources` に無いので作られない。
- タスクの写し（`tasks`）は既定で `/ask` に入る。入れたくないときは `tasks = false`。
- 決定の写し（`kiban/decisions.md`）は、`sources` に `decisions` があるときだけ作られる。

## データの置き場所

- **投稿の記録**: Bot の `paths.data_dir` の下の `weekly_state.json`（リマインドと同じ場所）。投稿した週・一覧に載せたタスク番号・追い投稿を済ませた番号を持つ。
  - 読めない・形が壊れているときは、空とみなさず投稿を止めてログに残す（同じ週の一覧を二度出さないため）。
  - 直近 60 週ぶんだけ残す。
- **タスク本体**: `/todo` と同じタスク DB。この機能は読んで、引き受けのときだけ `/todo assign` と同じ更新を行う。
- **決定・変更**: 統合アプリの決定の口を読むだけ。保存はしない。

## 権限

- 一覧と追い投稿は、投稿先チャンネルに Bot が書き込める必要がある。投稿先は @everyone から見えないチャンネルに限る（見えるときは止まる）。
- 通知は既定では鳴らさない（名前の表示だけ）。`mention_candidates = true` のときだけ、追い投稿で候補の人に通知が鳴る。候補の人に限り、一覧の担当の表示では鳴らさない。
- 引き受けは `/todo` と同じ（サーバーのメンバー・投稿先の閲覧権限・タスク機能の許可）。TaskCog の `_run` を通るので、権限の確認・本人だけへの返事・操作 ID・履歴の扱いが同じ。
- 決定・変更の節は、`[kiban]` の `enabled`・`app_url`・`key_file` が設定されているときだけ読む（この口専用の鍵）。

## 仕様の判断

- **「今週」**: 投稿の時点から 7 日さかのぼった期間に変わった決定（変更日時で判定。変更日時が無いものは決定日）。日付として読めない決定日は、決定日なしとして扱う。
- **「今週が期限」**: 今日から 6 日以内の期限で、期限切れではないもの。
- **未割当**: 期限の近い順（期限なしは最後）。ボタンは一覧に出した件だけ。
- **週の途中で有効にしたとき・Bot が止まっていたとき**: 同じ ISO 週（月曜始まり）の中なら、気づいた時点で 1 回だけ追いつく。次の週は次の時刻まで待つ。一覧が出ないまま週が終わるより、遅れて出すほうを選んだ。遅れて出ても同じ週に 1 回だけで、二重には出ない。
- **候補の人**: Bot はサーバーのメンバー一覧を読めない（特権インテントを使わない）。そこで、同じ部局のタスクで主担当・副担当になった実績がある人から選ぶ。その部局の未完了の件数が少ない順、同数は ID の小さい順、最大 3 人。部局の所属名簿は Bot にないので、実績のない人は候補に出ない。
- **追い投稿の条件**: 送る直前に、タスク DB で「まだ未割当・未完了」を確かめる。担当が決まった・完了した・見つからないときは送らず、その番号は閉じる。1 タスクにつき 1 回だけ。
- **二重投稿の防止**: 投稿の記録を先に保存してから送る。1 通も送れなかったときだけ記録を戻して次の回に出し直す。途中まで出た週は記録を残す（戻すと、前半が次の回にもう一度出るため）。
- **引き受けの二度押し**: 同じ人がもう一度押したら、変更せず「すでにあなたが主担当です」と返す。別の人が押したら、既に決まっていると返す。
- **時刻**: 日本時間。週は ISO 週。

## 残り

- Discord での実機確認（上の未確認の項目すべて）。
- 統合アプリの決定の口（`sources: decisions`）が、このリポジトリの版にはまだ無い。入るまでは「今週の決定・変更」の節は出ない。入ったら、契約文書 `docs/contracts/bot-datasource.md` に decisions の取り決めを書く（この版では契約文書は更新していない）。
- 部局の所属の名簿がないため、候補は「同じ部局で担当の実績がある人」だけ。
- 引き受けの後も、一覧は投稿時点の写し（完了や担当の変更は反映しない）。
- `@everyone` から見えるかどうかは、Bot の起動時に確かめる。投稿先の権限を後から変えたときは、再起動して確かめ直す。

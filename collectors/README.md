# 収集

委員会の Discord と LINE 公式アカウントのやりとりを記録に残し、Bot の `/ask` の資料や Discord への転送に使うための部品です。
どれも Bot ホストで動きます。トークンや鍵は、配置するホストのファイル（所有者だけが読める権限）から読み、リポジトリには置きません。

## Discord（`discord/`）

| ファイル | 内容 |
|---|---|
| `collect_discord_v2.py` | 読めるチャンネルのメッセージを、チャンネルごとの JSONL（1 行 1 メッセージ、リアクション付き）に差分で保存する。運用では Bot の `collector.py` が定期的に動かす |
| `fetch_attachments.py` | 添付ファイルの中身を保存する。JSONL には添付の名前しか無いので、API でメッセージを取り直して新しい URL を得てから落とす |
| `build_author_aliases.py` | 表示名とサーバーのニックネームの対応表（`_authors.json`）を作る。ユーザー ID を軸にして、過去の表示名も覚えておく。`/ask` の答えの著者名に使う |

Bot のトークンは、トークンのファイルから読みます（場所は各スクリプトの冒頭の設定）。

## LINE 公式アカウントの受信（`line-oa/`）

| ファイル | 内容 |
|---|---|
| `oa_server/oa_server.py` | LINE の Webhook を受ける常駐のサービス。署名を確かめて保管し、すぐ 200 を返す。取り込み用に、差分を返す `/export` と画像・ファイルを返す `/media/<messageId>` を持つ（どちらも取り込み用のトークンが要る） |
| `oa_pull.py` | 受け口の `/export` から新しい受信を取り、1 行 1 メッセージの JSONL に追記する。画像・ファイルの実体も保存する（LINE の側からは早く消えるため） |
| `oa_selftest.py`・`oa_server/oa_server_selftest.py` | 自己診断 |
| `systemd/` | 受け口と取り込みのユニットの例（取り込みはタイマーで動かす）。パスとユーザーは自分の環境に合わせる |

統合アプリのメールの画面も、同じ受け口の `/export` を読んで LINE の会話を出します（[docs/architecture.md](../docs/architecture.md) §3）。

## LINE 公式アカウントから Discord への転送（`line-oa-relay/`）

受け口に届いた LINE 公式アカウントの新しいメッセージを、Discord のフォーラムのスレッドへ転送します。

- 配置ごとの値（Discord のサーバー・チャンネル・ロールの ID、保存先のパス）は、同じフォルダの `site.json` から読みます。形は `site.example.json` で、既定の値はありません。
- 既定の設定では書き込みをしません。転送するには、明示して有効にした設定が要ります。
- 転送するのは有効にした時点より後の新しいイベントだけです。送った記録を残し、同じものを二度送りません。
- ログには件数などだけを書き、メッセージの本文は書きません。
- 個人の LINE アカウントの記録は扱いません（入力は LINE 公式アカウントの受け口だけ）。

試験は Linux 専用です（[docs/getting-started.md](../docs/getting-started.md) §4）。

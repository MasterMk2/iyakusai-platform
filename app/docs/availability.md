# 空き具合（委員の Google カレンダーの「予定あり」）

タスクの担当を決めるときの参考に、委員が自分の Google カレンダーの「予定あり」の時間だけをアプリに出す機能です（2026-11-20）。予定の題名・場所・メモは Google から送られてこないので、アプリにも入りません。つなぐかどうか、誰に見せるか、どこまで細かく見せるかは、委員が自分で決めます。

## 何ができるか

- **担当を選ぶ欄**（タスクの詳細の「担当者」「主担当」と、タスクの起票支援の各行）：選んだ人の、今日からタスクの期限まで（期限が無ければ 2 週間）の予定ありの日を、欄のすぐ下に出します。例：「11/21（金）午後・夜　11/23（日）終日」。「隠す」で消せ、選んだ状態はこのブラウザに残ります。
- **カレンダー**（タスクタブの「カレンダー」の月の表）：「委員の空き具合を重ねる」で、各日に「◯◯ 予定あり 午後」のように出します。出す人はチェックで選べます。月の表の 1 日には 2 人まで出し、残りは「ほか N 人」から日の一覧で見ます。日の一覧とスマホの週の一覧には、その日に予定がない人も「予定なし：…」と出します。
- **設定 › 空き具合の共有**：自分のカレンダーをつなぐ・見せる相手と見せ方を変える・やめる。

出るのは、今日から `horizonDays`（既定 42 日）先までです。今日より前と、それより先は出しません（分からない日を「予定なし」と見せないため）。

## つなぎ方（委員）

1. パソコンのブラウザで Google カレンダーを開き、使うカレンダーの「︙」→「設定と共有」→「特定のユーザーまたはグループと共有する」に、画面に出る委員会のアカウントのアドレス（`…@….iam.gserviceaccount.com`）を足します。権限は **「予定の表示（時間枠のみ、詳細は非表示）」** にします。
2. 設定 › 空き具合の共有に、カレンダー ID（ふだんのカレンダーなら Gmail のアドレス）・見せる相手・見せ方を入れて「次へ」を押します。共有ができていなければ、その場でそう出ます。
3. 画面に出る時間（2 日後の 3〜5 時台の 25 分）に、Google カレンダーで予定を 1 つ入れて「確かめる」を押します。その時間が「予定あり」になったのを見て、つなぎます。確かめたあと、その予定は消してかまいません。

3 の手順は、ほかの人のカレンダー ID を入れてその人の予定を自分の名前で出すことを防ぐためです（カレンダーに書き込める本人しか、その時間を埋められない）。1 つのカレンダーをつなげるのは 1 人だけです。

## 見せる相手と見せ方

| 選択 | 動き |
|---|---|
| 委員全員 | ログインできる委員全員（臨時スタッフは除く） |
| 部局 | 選んだ部局の委員（所属の表記は委員の所属と同じ。役員会も選べる） |
| 人 | 選んだ委員 |
| 午前・午後・夜だけ（既定） | 0〜12 時を午前、12〜18 時を午後、18〜24 時を夜として、予定がある部分だけを出す。時刻はどの答えにも入らない |
| 時間帯 | 「14:00–16:00」のように時刻も出す |

本人はいつでも自分の分を見られます。最初の既定は「役員会」と「午前・午後・夜だけ」です。どの選択も、サーバーが答えるたびに確かめます（画面で隠すだけにはしていません）。カレンダー ID は本人にだけ見え、ほかの人への答えには入りません。

## 状態の出し方

| 状態 | 画面 |
|---|---|
| ok | 予定ありの日を出す。ない日は「予定なし」 |
| 少し前の情報（stale） | Google を読めなかったので、最後に読めた分を時刻つきで出す（12 時間たつと出さない） |
| 共有が外れた（not_shared） | 何も出さず、「共有が外れています」と出す |
| 読めない（error）・まだ（pending） | 何も出さず、その旨を出す |

読めないときに「予定なし」と見せることはありません。

## 仕組みとデータ

- 統合アプリが `refreshMinutes`（既定 15 分）ごとに、つないだ委員のカレンダーを Google の FreeBusy API（`freebusy.query`、スコープは `calendar.freebusy` だけ）でまとめて読みます。1 回の問い合わせは 50 カレンダーまで（Google の上限）。
- 予定ありの時間帯は**メモリにだけ**置きます。ファイルにもバックアップにも書かないので、再起動すると最初の読み込みまで「まだ」になり、やめた委員の分はすぐに消えます。
- `availability.sqlite3`（`SMM_MAIL_DIR`、受信箱の隣）にあるのは、委員ごとのカレンダー ID・見せる相手・見せ方・つないだ日時と、確かめ中の時間だけです。運用のバックアップ（`ops/backup.ts`）が `mailbox/availability.sqlite3` として複製します。
- やめると、記録とメモリの分が消えます。Google カレンダーの共有は本人が外します。
- 委員でなくなった人（ログインを止められた人・臨時スタッフ）の分は読まず、出しません。
- デモ（`SMM_AUTH_MODE=demo`）では Google の代わりに合成の予定を作ります。最初の 3 人がつないだ状態で始まり、`.invalid` で終わるカレンダー ID だけが「共有済み」として答えます。

## 知っておくこと

- Google の終日の予定は、最初「予定なし」になっています。終日の予定を空き具合に出したいときは、Google 側でその予定を「予定あり」にします。
- 予定が「非公開」でも、時間枠は「予定あり」として出ます（題名は Google の時点で来ません）。
- この 2 つは Google の動きで、この委員会のアカウントではまだ確かめていません。
- 担当の欄は、Bot が出す担当の案（タスクの起票支援）には使いません。iCal の取り込み URL にも入りません。
- Workspace（iyakusai.com）のアカウントのカレンダーは、組織の外部共有の設定によって、サービスアカウントに共有できないことがあります。

## 本物の Google で 1 回だけ確かめる（運用）

画面でつなぐ前に、サービスアカウント・Calendar API・共有がそろっているかを確かめられます。アプリのコンテナの中で：

```sh
node dist/server/ops/availability-check.js <カレンダー ID>
```

`availability.json` を読み、そのカレンダーの今日から 7 日を 1 回だけ問い合わせて、「読めた（予定ありの件数）」「共有されていない」「失敗の種類」だけを出します。時刻や Google の答えの中身は出しません。

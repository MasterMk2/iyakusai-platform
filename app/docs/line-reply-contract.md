# LINE 返信契約（手動返信・模擬送信）

[LINE 連携](line-integration.md)の手動返信の契約。実装は `src/server/line/reply.ts`、`src/server/line/connector.ts`、
`src/server/http/line-routes.ts`。**送信は模擬コネクターだけで、実際の LINE には送信しない。**
実送信アダプター・アクセストークン・料金プランの変更は承認が必要（LN03・LN04）。

## 1. 送信方法と時間の扱い

| 項目 | この準備版の扱い | 根拠（要旨） |
| --- | --- | --- |
| 応答メッセージ（応答トークン） | **使わない・保存しない。** 封筒に含まれていれば拒否する。 | 応答トークンは 1 回限りで、受信から約 1 分以内の使用が前提（それ以降は保証されない）。再配送されたイベントのトークンは、元のトークンが使われた場合や 20 分を過ぎた場合は使えない。既存の Bot が使っている可能性もある。 |
| プッシュメッセージ | 手動返信の既定の方法。確認画面で「プッシュ（模擬）」と表示する。応答から自動で切り替えることはない。 | 受信から時間が経った手動返信は応答では送れないため。 |
| 通数 | 確認画面に「月間の通数に数えられる」「残り通数・追加料金はこのアプリで確認していない」と表示。グループは人数分。 | プッシュは月間の上限に数えられ、応答は数えられない。グループ宛ては受け取る人数分。 |
| 受付と配信 | HTTP 200 相当は「受付済み（模擬）」。配信・既読は確認できないと表示し、「配信済み」とは扱わない。 | API の 200 は要求を受け付けたことだけを示す。 |
| 再送キー | 送信意図ごとに 1 回だけ UUID を作り、すべての再試行で同じ値・同じ宛先・同じ本文を使う。 | 同じキーは 24 時間、受付済みの重複として 409（受付済みの要求 ID 付き）で返る。24 時間を過ぎると新しい要求として送られうる。 |
| 再送の安全期間 | 最初の試行から **23 時間 50 分**（24 時間から時計のずれの余裕 10 分を引いた提案値）。過ぎたら要確認にして送らない。 | 同上。 |

## 2. 送信できる相手（保存済みの観測だけで判定）

| 送信先 | 送信できる条件 | 送信できない例 |
| --- | --- | --- |
| 1:1 | 友だち追加（follow）を観測し、その後に友だち解除（unfollow）を観測していない。または最後の 1:1 メッセージから 7 日以内。 | 友だち解除・ブロック、7 日を過ぎた非友だち、観測がない。 |
| グループ・トークルーム | 参加（join）を観測し、退出していない。かつ人数を観測済み（全員に届く旨と人数を確認画面に表示）。 | 退出済み、人数が不明（閲覧のみ）。 |
| 旧履歴 | 常に不可。 | すべて。 |

送信先は保存済みの会話の送信先だけから決める。クライアントから宛先・方法・「確認済み」フラグは受け付けない（厳格なスキーマで 400）。
グループ宛てを個人宛てに変えることはない。自動返信・一斉送信はない。

## 3. 状態遷移

```text
[下書き v1..n]（作成者ごと・版番号付き）
   │ 確認（POST preview）: 権限・送信先を再確認
   ▼
[確認] 5 分・1 回限り・作成者 + 下書きの版 + アカウント + 送信先の指紋 + 本文のハッシュに結び付く
   │ 送信（POST send: consentId, operationId, draftId, draftVersion, body）
   │   再確認: 有効な利用者・閲覧 + 返信権限・確認・版・本文・送信先の条件と指紋
   │   1 つのトランザクションで: 確認を消費 → 送信意図（不変）を作成 → 試行 1 を開始 → 下書きを削除 → 保存
   │   保存に失敗 → 何も送らない（確認は未消費のまま）
   ▼
[pending] ── コネクター呼び出し ──┬→ [accepted]（200 / 409 重複受付）… 再送しない
                                   ├→ [failed・再試行可]（送信前の失敗、429 は指定時刻以降）
                                   ├→ [failed・最終]（権限・設定・送信先の条件）… 新しい返信として作り直す
                                   └→ [unknown]（タイムアウト・5xx・結果を保存できなかった）
[failed・再試行可] / [unknown] ── 明示的な再試行（expectedAttempts）──→ [pending]（同じ再送キー）
   安全期間を過ぎた、送信先の条件や指紋が変わった → [manual_review]（送らない・新しいキーを作らない）
```

- 「処理中」の試行がこのプロセスで実行中でなければ（結果の保存に失敗した、再起動した）、表示は `unknown`。再試行でその試行を `unknown` として閉じてから同じキーで送る。
- 結果の保存に失敗した場合は 503 `result_not_saved` を返す。送信意図は `pending` のまま保存済みなので、再起動後も同じキーで再試行でき、提供元が同じキーを受付済みとして覚えていれば 409 の重複受付として `accepted` になる（二重送信にならない）。模擬コネクターはプロセスの再起動でキーを忘れる（8 の制限）。
- 自動の再送・別チャネル（メール等）への切り替え・新しいキーでの再送はしない。

## 4. 同時実行と再実行

| 状況 | 結果 |
| --- | --- |
| 同じ `operationId`・同じ利用者・同じ会話・同じ本文の再送 | 既存の送信意図をそのまま返す（`replayed: true`）。コネクターは呼ばない。 |
| 同じ `operationId` で本文・会話・利用者が違う | 409。 |
| 同じ確認を別の `operationId` で同時に使う | 1 件だけ成功し、ほかは 409（成功した送信意図の ID を `details` に含む）。 |
| 確認後の本文の変更・下書きの更新・期限切れ・他人の確認 | 409（もう一度確認が必要）。 |
| 再試行の同時実行 | `expectedAttempts` が一致した 1 件だけが試行を追加し、ほかは 409。実行中は 409。 |
| 確認待ちが多すぎる | 本人の期限内・未使用の確認が 10 件、または期限内の確認の記録が全体で 100 件に達すると、新しい確認は 409。ほかの利用者の確認は消さない（暫定値・LN09）。 |

画面は確認の表示ごとに `operationId` を 1 回だけ作り、送信中はボタンを無効にする。確認後に本文を編集すると確認は破棄される。

## 5. 権限の再確認

下書き・確認・送信・再試行のたびに、現在の状態から次を確認する：有効な利用者であること、アカウントの閲覧権限と返信権限、会話が存在すること。
送信記録は会話の閲覧権限がある利用者だけが見られる。下書きは作成者本人だけが見られる。

## 6. 記録とプライバシー

- 会話の履歴・送信記録には、操作者・方法・時刻・操作 ID の先頭・結果だけを残す。本文は送信意図（会話の内容として閲覧権限で保護）と下書きにだけ保存し、監査ログ・履歴には入れない。
- 確認値はハッシュだけを保存する。アクセストークン・ヘッダー・応答トークンは存在せず、保存しない。再送キーと外部 ID は API で返さない（送信先 ID は末尾 4 文字だけ表示）。

## 7. API（実装済み・模擬）

| メソッド | パス | 権限 |
| --- | --- | --- |
| GET | `/api/inbox?source&mailboxId&lineAccountId&q&status&label&assignee&page&pageSize`（受信箱と LINE アカウントの同時指定は 400）、`/api/inbox/labels` | 各ソースの閲覧 |
| GET | `/api/line/accounts`、`/api/line/conversations/:id` | 閲覧 |
| GET/PATCH/POST | `/api/line/conversations/:id/assignees`・`/triage`・`/notes` | 編集 |
| PUT/DELETE | `/api/line/conversations/:id/reply/draft` | 閲覧 + 返信 |
| POST | `/api/line/conversations/:id/reply/preview`、`/reply/send` | 閲覧 + 返信 |
| GET | `/api/line/outbox/:intentId` | 閲覧 |
| POST | `/api/line/outbox/:intentId/retry` | 閲覧 + 返信 |
| GET/PUT | `/api/admin/line/access`、GET `/api/admin/line/audit` | 権限管理者（内容は見えない） |
| POST | `/api/demo/line/release`、GET/PUT `/api/demo/line/connector` | デモ管理者・デモモードだけ（リポジトリ内の合成バッチと模擬結果。受け取り口ではない） |

既存の Host・Origin・`Sec-Fetch-Site` の検査、trusted-proxy の識別、`no-store` はすべての LINE ルートにも適用される。
LINE を無効にした場合、LINE のルートは存在しない（404）。

## 8. 模擬コネクター

`MockLinePushConnector` は I/O を一切行わない。受付済みの再送キーを 24 時間覚え、同じキーには重複受付を返す。
デモ管理者（デモモード）とテストは次の結果を指定できる：受付、送信前の失敗、受付後に応答が失われる、サーバーエラー（結果不明）、429、403、未設定、送信先の条件不一致。

**制限**：模擬コネクターが覚えた再送キーはプロセスのメモリだけにあり、アプリのプロセスを完全に再起動すると消える。
再起動後の回復テスト（`tests/api/line.test.ts`）は、外部の提供元側の重複判定を模すために同じ模擬コネクターのインスタンスを意図的に引き継いでいる。
したがって、このテストが示すのはアプリ側の送信意図・再送キーの保存と再利用だけで、実際の LINE の重複判定や、プロセス再起動をまたいだ模擬送信の保証ではない。
「受付済み」は受付を示す模擬結果で、利用者への配信を示さない。実際の重複判定の確認は実送信アダプターの承認後（LN03）。

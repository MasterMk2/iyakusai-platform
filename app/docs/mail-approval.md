# メールの送信前の承認（2026-11-11）

メールを書いた人がそのまま送るのではなく、校閲の権限を持つ人が承認したときに送られる仕組みです。書き慣れていない委員のメールを、上級生が確かめてから出すために使います。

## だれのメールが承認待ちになるか

受信箱ごとに決まります。次のどちらかに当たる人が、その受信箱のアドレスを差出人にして書いたメールは、送信されずに承認待ちになります。

- その受信箱の送信の権限を持っていない
- 送信の権限は持っているが、その受信箱で「承認必須」が付いている

承認待ちにできるのは、校閲者が 1 人以上いる受信箱だけです。校閲者がいない受信箱は今までどおりで、送信の権限が無い人はメールを書けません。臨時スタッフは書けません。

アプリは学年を持っていません。1 年生などを承認待ちにしたいときは、その人に送信の権限を付けないか、「承認必須」を付けます。

## 権限

設定 › メールの権限で、受信箱ごとに権限の管理者が付けます。

| 権限 | 付ける先 | できること |
|---|---|---|
| 校閲 | 委員・部局 | その受信箱の承認待ちを読む、承認して送る、直す、差し戻す |
| 承認必須 | 委員 | 送信の権限があっても、その受信箱からのメールは承認待ちになる |

- 校閲の権限だけでは、自分のメールをそのまま送ることはできません。自分が書いたメールは、自分では承認も差し戻しもできません。
- 年度の切り替え（権限の棚卸し）の一覧に、校閲と承認必須も出ます。

## 流れ

1. 書く人は、いつもの作成欄で書きます。差出人が承認の要る受信箱のときは、ボタンが「承認を依頼する」になり、校閲者へのひとことを添えられます。依頼しても相手には何も送られません。
2. 校閲者には、メールのタブの「承認待ち」とホームに件数が出ます。開くと、送る内容・添付・送信前のチェックが見えます。
3. 校閲者は次のどれかをします。
   - **承認して送信**：確認のチェックを入れて押すと、その場で送られます。
   - **直す**：宛先・CC・BCC・返信先・件名・本文・回答期限を直して保存し、そのあと承認します。添付は変えられません。直した項目と、依頼したときの内容は、書いた人にも見えます。
   - **差し戻す**：理由を書いて戻します。
4. 差し戻されたメールは、書いた人の「承認待ち」に理由と一緒に出ます。書いた人は作成欄で直して出し直すか、取り下げます。承認待ちのあいだも取り下げられます。

状態は、承認待ち・差し戻し・送信中・送信済み・送信できたか不明・取り下げの 6 つです。

## 送られるメール

- 差出人は受信箱のアドレスで、署名は書いた人のものです（作成欄が本文に入れたもの）。
- 送信の記録（`outgoing`）の送信者は書いた人です。1 時間あたりの送信数の上限も、書いた人の分として数えます。承認した人は依頼の履歴に残ります。
- 返信の「送ったらスレッドを完了にする」と回答期限は、依頼のとおりに働きます。回答期限は、書いた人か承認した人のどちらかがその受信箱の編集の権限を持っているときに付けられます。
- 記録用のアドレスへの BCC、送信済みのメールの保存は、ふつうの送信と同じです。

## 二重に送らないための決まり

- 依頼には版番号があります。承認・修正・差し戻し・取り下げ・出し直しは、画面が読んだ版のときだけ通ります。校閲者が見ていない内容が承認されることはありません。別の人が先に操作していたら、最新の内容を読み直すよう伝えます。
- 1 つの依頼が送れるのは 1 回だけです（依頼ごとに送信の識別子を 1 つ持ち、送信の本体が同じ識別子を 2 度送りません）。
- メールサーバーが受け付けなかったときは、送られていないので承認待ちに戻ります。送信の途中で接続が切れたときは「送信できたか不明」になり、同じ依頼をもう一度送ることはできません。Gmail の送信済みか相手への確認で確かめ、届いていなければ新しく書いて出し直します。
- 1 人が同時に待たせられる依頼（承認待ちと差し戻し）は 10 通までです。

## 見られる人

依頼の内容と添付を見られるのは、書いた人と、その受信箱の校閲者だけです。ほかの人には「見つからない」と答えます。監査の記録には、依頼の ID と受信箱だけを書き、アドレス・件名・本文は書きません。

## 保存

`mail.sqlite3` に表を足しています（既存の表は変えていないので、前の版のアプリも同じファイルを開けます）。

| 表 | 内容 |
|---|---|
| `review_grants`・`department_review_grants` | 校閲の権限（委員・部局） |
| `approval_required` | 承認必須の印 |
| `send_requests` | 依頼。いま送る内容と、依頼したときの内容 |
| `send_request_attachments` | 依頼の添付。送信・取り下げのあとは消します |
| `send_request_history` | 依頼の履歴 |

添付はデータベースの中に持ちます。バックアップは `mail.sqlite3` を丸ごと写すので、承認待ちの添付も含まれます。

## API

どれもメールの画面と同じ確認（ログイン、試行の一覧、しばらく使っていない端末でのパスワードの再入力）を通ります。送信の設定（`send`）が無いサーバーにはありません。

| メソッドとパス | 内容 |
|---|---|
| `GET /api/mail/approvals` | 自分が承認する依頼、自分の依頼、済んだもの |
| `GET /api/mail/approvals/:id` | 依頼 1 件 |
| `GET /api/mail/approvals/:id/attachments/:idx` | 添付のダウンロード |
| `POST /api/mail/approvals` | 承認を依頼（multipart。`message` と `attachments`） |
| `PUT /api/mail/approvals/:id` | 差し戻された依頼を直して出し直す（multipart） |
| `PATCH /api/mail/approvals/:id` | 校閲者が直す |
| `POST /api/mail/approvals/:id/approve` | 承認して送信 |
| `POST /api/mail/approvals/:id/return` | 差し戻す |
| `POST /api/mail/approvals/:id/withdraw` | 取り下げる |

- `GET /api/mail/send/options` の `from` には、承認の要る受信箱も入ります。どれが承認の要る受信箱かは `approvalMailboxIds` で分かります。
- 承認の要る受信箱から `POST /api/mail/send` で送ろうとすると、403（`approval_needed`）で断ります。
- `GET /api/mail/status` の `approvals` に、自分が承認する件数と、差し戻された自分の依頼の件数が入ります。
- `PUT /api/mail/admin/access` は、`review`（委員・部局）と `approval`（委員）も受け付けます。

## まだ無いもの

- Discord への知らせ（依頼が来た・承認された・差し戻された）。いまはアプリの中の件数表示だけです。
- 団体への一斉メールと公式LINE の承認。「承認必須」の付いた人は、その受信箱から一斉メールを送れません。

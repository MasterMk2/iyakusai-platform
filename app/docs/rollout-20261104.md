## 統合アプリ

### 新しい保存ファイル

本番（Discord ログイン）では、受信箱の保存先（`SMM_MAIL_DIR`）に次のファイルが起動時に作られます。どれも `ops/backup.ts` の複製に入り、件数を `manifest.json` に記録します。

| ファイル | 中身 |
|---|---|
| `decisions.sqlite3` | 決定事項と履歴 |
| `organizations.sqlite3` | 団体の台帳・履歴・一斉送信 |
| `calendar.sqlite3` | 予定・履歴・取り込み URL のハッシュ |
| `payments.sqlite3` | 請求・入出金明細・照合・会計の権限 |
| `dayof.sqlite3` | 当日の期間・決め方・発信者・連絡 |
| `rollover.sqlite3` | 年度の切り替えの実行の記録 |

`mail.sqlite3` には表 `message_due` が足されます（既存の表は変えない）。物品の `rental.sqlite3` には `supply_*` の表が足されます。

どのファイルも、開けないときはその機能だけが止まり、ほかの機能は動きます（起動のログに出る）。

### 環境変数

- `SMM_CALENDAR_ICAL`：未設定なら Discord ログインでは off。`on`・`off` 以外の値では起動しません。on にするときは、前段のプロキシで `/api/calendar/ical/<トークン>.ics` を（ブラウザ向けの認証の外で）統合アプリへ通し、プロキシのアクセスログの保存期間と閲覧者を決めます（URL にトークンが入るため）。
- ほかに新しい環境変数はありません。

## Bot

本番の Bot は、このリポジトリの `bot/` と違うファイルがあります（本番にだけある手直し）。**入れ替える前に、本番のファイルとこのリポジトリの `bot/` を突き合わせ、本番にだけある変更を残すか取り込むかを決めます。** この版では次のファイルが変わっています（`git diff --name-only` で確かめられます）。

- `src/iyakusai_bot/` の約 30 ファイル：新しい `access.py`・`access_check.py`・`audit.py`（権限の表と監査ログ）、`notify.py`（送り先）、`weekly_*.py`（週1回の一覧）、`write_guard.py`（書き出すファイルの【AI】の接頭辞）、`decisions_logic.py`。ほかに、権限の判定を入れた命令の口（`task_cog.py`・`assistant_cog.py`・`images.py`・`screening_cog.py` など）と `config.py`・`bot.py`・`kiban.py`
- `gateway/bot_task_gateway.py`（タスク API の「自分の持ち」）
- `src/config.example.toml`（`[weekly]`・`[notify]`・`[permissions]` の例）

設定：

- 決定事項を Bot に写すときは、`[kiban]` の `sources` に `"decisions"` を足します（統合アプリを先にこの版にしてから）。
- `[weekly]`・`[notify]`・`[permissions]` は、使うときだけ書きます。週1回の一覧の送り先は `@everyone` から見えないチャンネルにします（見えると起動時に止まる）。
- 登録するコマンドが権限の表（`access.py` の `COMMAND_KINDS`）に無いと、管理者のロールにだけ開きます。本番にだけあるコマンド（例：`/line返信`）があれば、表に足してから入れ替えます。

## 入れ替えの順番

1. 統合アプリの保存先のバックアップを取る（`ops/backup.ts`）。
2. 統合アプリをこの版に入れ替え、起動のログで各機能が開けたことを見る。
3. Bot ホストのタスク API を更新する（自分の持ちを使うとき）。
4. Bot を、本番のファイルと突き合わせたうえで入れ替える。設定の節は、確かめながら 1 つずつ足す。

## 切り戻しの注意

- **Bot を先に戻す**：統合アプリをこの版より前へ戻すときは、先に Bot の `kiban.sources` から `"decisions"` を外して Bot を再起動します。旧版の統合アプリは知らない `sources` を 401 で断るので、外さずに戻すと物品・受信箱の写しまで更新が止まります。
- **メールの履歴**：この版で期限を付けると `mail.sqlite3` の履歴に `due`・`reply_wait` の行が入ります。旧版では、その行が種類の名前なしで出ます（ファイルは開ける）。
- 新しい保存ファイルは旧版では使われません。消さずに残しておけば、もう一度この版にしたときにそのまま使えます。

# カレンダーと年間の予定

委員会の締切・会議・学務の手続き・行事を、ひとつの月の表（PC）と週ごとの縦の一覧（スマホ）で見るための機能です。タスクタブの「カレンダー」の表示として入っており、上のタブは増えていません。毎年の予定を一覧で見られ、次の年度へ写す作業の元になります。自分のカレンダー（Google カレンダーなど）へ取り込むための、本人だけの URL も出せます。

## 何ができるか

- **月の表**：予定（予定の題名・種類・時刻）と、タスクの期限を同じ日の中に並べます。完了したタスクは薄く出ます（「完了したタスクを隠す」で消せます）。日付の数字か「ほか N 件を見る」を押すと、その日の一覧が下に出ます。
- **スマホ**（幅 679px 以下）：表の代わりに、その週の 7 日を縦の一覧で出します。前へ・次へは週ごとに動きます。
- **絞り込み**：部局で絞る（その部局の予定と、委員会全体の予定。タスクは部局のタグで絞ります）。「自分に関係するもの」は、自分の部局の予定と委員会全体の予定、自分が担当・副担当のタスクに絞ります。
- **タスクの絞り込みとの関係**：カレンダーのタスクは、タスクの一覧の部局の選択（上の部局）だけで絞ります。検索・状態・担当・期限の絞り込みは、カレンダーでは使いません（その欄はカレンダーの表示では隠れます）。
- **予定の追加・変更・削除**：委員全員が追加と変更をできます。削除は、登録した人と権限の管理者だけです。変更するたびに履歴が残ります。
- **毎年の予定**：「毎年」にした予定を、選んだ年の日付で一覧にします。部局で絞れます。月の表では、毎年の予定が該当する年の同じ月日にも出ます。
- **ホームの「近づいている予定と期限」**（2026-11-04 に「近づいている締切」から改名）：予定は、前もって知らせる日（14 日前・7 日前・3 日前・1 日前・当日から選ぶ）に入ったものを出します。年をまたぐ期間（12 月から 1 月）も、翌年の毎年の予定を出します。タスクは、期限が 7 日以内の自分の未完了のものを出します。項目を押すと、その日のカレンダーが開きます（タスクはそのタスク）。今日・明日の項目の数は、ホームの上の「対応が必要な件数」に「今日・明日の予定と期限」として出ます（今日が期限の自分のタスクは「今日が期限のタスク」に数えるので、ここでは数えません）。カードは受信箱・メールの期限のすぐ下、タスクの残数の上にあります。
- **iCal の取り込み URL**：本人だけの URL を作ると、Google カレンダーの「URL で追加」に貼れます。中身は、自分の部局の予定と委員会全体の予定、自分が担当・副担当の未完了タスクの期限です。題名と日付だけで、すべて終日の予定になります（時刻・メモ・担当者・ほかの人の情報は入りません）。

## 使い方

1. 「タスク」タブを開き、表示の形で「カレンダー」を押します。ホームの「近づいている予定と期限」の予定を押すと、その日のカレンダーが開きます。
2. 「予定を追加」で題名・種類・日付（終日か時刻）・部局・メモを入れ、「毎年」「知らせる日」を選んで保存します。
3. 変更は予定を押して開きます。ほかの人が先に変更していた場合は「ほかの人が先に変更しました」と出て、最新の内容を読み込みます。入力した内容は画面に残るので、確かめてからもう一度保存します。
4. 毎年の予定の、別の年に出ている項目を押すと、その予定の元の日付で開きます。日付を変えると、すべての年の表示が変わります。
5. 取り込みは、カレンダーの下の「自分のカレンダーに取り込む」で「取り込み用の URL を作る」を押します。URL は作ったときだけ表示されます。忘れたら「作り直す」を押すと新しい URL になり、前の URL は止まります。「取り込みを止める」で、すべての URL が止まります。

## データの置き場所

- 予定と履歴：`calendar.sqlite3`。Discord でのログイン（`SMM_AUTH_MODE=discord`）では、委員会の受信箱のフォルダ（`SMM_MAIL_DIR`）の中に、メールの `mail.sqlite3` と並んで置かれます。そのためメールのフォルダのバックアップに含まれます。
- 運用のバックアップ（`ops/backup.ts`）も、このファイルを `mailbox/calendar.sqlite3` として SQLite のオンラインバックアップで複製し、整合性と件数（`calendar.events`・`calendar.event_history`・`calendar.ical_subscriptions`・`calendar.event_requests`）を確かめて、manifest に載せます。この複製から戻せば、予定・履歴・取り込み URL の記録も戻ります。
- 取り込み用の URL：同じファイルの中に、URL の**ハッシュだけ**を保存します（URL そのものは保存しません）。
- 他のモード（`account`・`account-mock`・`trusted-proxy`）では、状態のファイル（`SMM_DATA_FILE`）と同じフォルダに置きます。これは合成データの統合デモ用で、運用のバックアップの対象ではありません。
- Discord でのログインで受信箱（`SMM_MAIL_DIR`）を設定せずに起動したときは、カレンダーを使いません（503。決定事項と同じ）。以前は状態のファイルのフォルダに別の `calendar.sqlite3` を作っていたため、受信箱を一時的に外して起動しただけで予定が空に見え、その間の登録がバックアップされないファイルに分かれていました（2026-11-04 に変更）。
- デモ（`SMM_AUTH_MODE=demo`）では、デモのデータファイルのフォルダ（既定は `data/`。Git の管理外）に置きます。予定が 1 件もないときに起動すると、合成の予定（名前に「（例）」と付いたもの）を入れます。
- 予定の履歴（`event_history` の表）には、作成・変更・削除の前の内容が残ります。画面からは見られませんが、削除した予定の内容はここで確かめられます。
- 新規の保存の依頼番号（`event_requests` の表）は 1 日だけ残し、それより古いものは消します。

## 権限

| 操作 | 誰ができるか |
|---|---|
| 予定を見る・追加する・変更する | 委員（臨時スタッフとログインを止められた人は使えません） |
| 予定を削除する | 登録した人と、権限の管理者 |
| 取り込み用の URL を作る・作り直す・止める | 本人（ほかの人の URL は見られず、止められません） |
| 取り込み用の URL で中身を読む | URL を持つ人（ログインは要りません。下の「取り込みの経路」を見てください） |

権限の確認はすべてサーバー側で行い、画面では隠すだけにはしていません。画面では、削除できない人には削除の入口を出しません。

## 保存のしくみ

- 変更は、読み込んだときの版（版番号）と一緒に送ります。ほかの人が先に変えていれば 409 で止まり、最新の内容を読み込みます（入力は残ります）。
- 同じ内容の保存をもう一度送った場合（最初の応答が届かなかったとき）は、すでに保存された版として成功を返します。「ほかの人が先に変更しました」とは出ません。
- 新しい予定の保存は、画面の一回の入力ごとに依頼の番号を付けて送ります。応答が届かずにもう一度送っても、予定が二件できません（同じ番号には最初の予定を返します。番号は予定の内容が変わると新しくなります）。

## 有効にする方法

環境変数 `SMM_CALENDAR_ICAL` で、取り込み用の URL の機能を切り替えます。

| 値 | 動き |
|---|---|
| 未設定（既定） | デモでは on、Discord などの運用では off |
| `on` | 取り込み用の URL を出す（運用では、委員会の経路を通せる状態のときだけ on にしてください） |
| `off` | 取り込みを、どのモードでも止める。画面からも取り込みの欄が消える |

それ以外の値では起動しません。カレンダー自体は、この設定に関係なく使えます。

カレンダーの保存ファイルを開けなかったときは、カレンダーだけが 503（`calendar_unavailable`）を返します。ホームの「近づいている予定と期限」は、この応答のときは枠ごと出しません。タスクや他の機能は使えます。

### 取り込みの経路（リバースプロキシ）

取り込みの URL は `/api/calendar/ical/<トークン>.ics` で、ログインなしで読める経路です。運用では次を確かめてください。

- 前段のリバースプロキシは、この path を統合アプリへ通すこと（ほかの `/api/` と同じ規則で足りますが、ブラウザ向けの認証をかけている場合はこの path だけ認証の外に出すこと）。
- プロキシのアクセスログには、URL（トークンを含む）が残ります。ログを読める人が URL を使えてしまうため、ログの保存期間と閲覧者を決めてください。統合アプリ自身はリクエストの URL を記録しません。
- プロキシを経由する要求は、`X-Forwarded-For` の最後の値をアドレスとして数えます（信頼するプロキシからの要求だけ。ログイン系と同じ規則）。
- 存在しないトークン・止めた取り込み・もう在籍していない人の取り込みは、すべて同じ 404 を返します。推測での総当たりは、同じアドレスから 10 分に 20 回までの不明なトークンで止まります（全体では 10 分に 300 回まで）。有効なトークンは数えないので、使われている取り込みが止まることはありません。
- 中身は 10 分ほど保存して使い回します。取り込む側（Google など）の更新も、その程度の遅れを見込んでください。

- 単体試験（`tests/unit/calendar-shared.test.ts`）：入力の検査（題名と部局名の改行・制御文字を含む）、JST の日付、閏年の 2 月 29 日（翌年は 2 月 28 日）、予定の期間判定、タスクへ開く日付の検査、iCal の文字の扱い（エスケープ・75 オクテットの折り返し・CRLF・終日だけの書式）、トークンとハッシュ、不明なトークンの回数制限。
- 保存の試験（`tests/api/calendar-store.test.ts`）：版番号と競合、同じ内容の再送、履歴、変更なし、依頼番号による二重の作成の防止と、番号の期限、削除の履歴、期間・毎年の並び、取り込みの表にトークンそのものが書かれないこと。
- HTTP の試験（`tests/api/calendar-http.test.ts`）：デモの人物での作成・変更・古い版の拒否・削除の権限、依頼番号の再送（同じ人は一件、別の人は別の件、削除済みは作り直さない）、同じ内容の再送、月の表と毎年の予定（閏日の基準の日付を含む）、ホームの近づく締切（年またぎを含む）、取り込み（Cookie もなし・Origin もなしで読めること）、同じ 404、作り直しと停止、回数の制限と有効な URL が止まらないこと、取り込みを切ったときの応答、保存ファイルを開けないときの 503。
- 運用のバックアップの試験（`tests/api/calendar-backup.test.ts`）：`mailbox/calendar.sqlite3` が複製され、履歴と件数が manifest に載り、取り込み URL の本体が複製に含まれないこと。
- 型検査・ESLint・ビルドは通っています。
- 画面（Playwright）の試験は、このブランチでは実行していません（ポートの衝突を避けるため。統合のときにまとめて実行します）。

## 決めたこと（前提）

- 部局の名前は、委員の役職ラベル（`departmentsOfLabel`）と、タスクの部局の表示名が**同じ表記**であることを前提にしています。違うと、部局で絞るときに片方が落ちます。運用の前に、両方の表記を確かめてください。
- 年の選択は、1 月から 12 月の暦年です（年度の始まりは決めていません）。毎年の予定は、登録した日付の月日を、選んだ年に写すだけです。次の年度へ写す作業（別の担当）が、新しい予定として登録してください（`copiedFrom` の欄は、写したもとの予定を覚えるためにあります）。
- 閏年の 2 月 29 日は、閏年以外では 2 月 28 日として表示します。元の日付は変わりません。
- タスクの「知らせる日」は 7 日で固定しています（タスクに設定はありません）。
- 取り込みには時刻を入れません（題名と日付だけ。外に出さない側を選びました）。時刻を入れる判断は、委員会で決めてから変えます。
- 取り込みは、既定では運用で止めています（外に出さない側）。使うときは `SMM_CALENDAR_ICAL=on` にします。

## 残り

- 年度の切り替え（予定を次の年度へ写す機能）は別の担当の仕事です。この機能は、写しやすいように「毎年」と月日の保存、`copiedFrom` の欄を用意しただけです。
- 取り込みの URL をプロキシの経路で実際に通す試験は、運用の環境でしかできません（ここでは合成のリクエストだけで確かめています）。
- Playwright の画面試験は、このブランチでは実行していません（ポートの衝突を避けるため。統合のときにまとめて実行します）。
- 月の表の見た目と、タスクの一覧からカレンダーへ切り替えたときの見た目は、PC の幅と 320〜679px の幅で確かめる必要があります（画面の確認は未実施）。
- 予定に添付や繰り返しの設定（毎月・毎週）はありません。
- 削除の取り消しは画面にはありません。誤って消したときは、システム課が履歴から内容を確かめます。

# メールの期限（回答期限・返事待ち・対応期限）

委員会のメール（`SMM_AUTH_MODE=discord` の受信箱）に、2 種類の期限を付けられるようにしたものです（2026-11-03）。名前の使い分けは次のとおりです。

- **回答期限**：委員会が送ったメールに付ける、相手からの返事を待つ期限の日付。付くと、そのスレッドは「返事待ち」になる。
- **返事待ち**：回答期限が付いて、相手の返信がまだ届いていない状態のこと（スレッドの札・一覧・ホームでの呼び名）。回答期限を過ぎたら、一覧とホームに出す。
- **対応期限**：受け取ったメールの対応の期限。対応状況（未対応・対応中・保留・完了）とは別に持つ。受け取ったメールにも送ったメールにも付けられる。

公式 LINE は対象外です。期限の記録は、委員会のメールと同じ `mail.sqlite3` に置きます。

## 1. できること

| 場面 | 操作 |
|---|---|
| メールを送る | 「回答期限（任意）」に日付を入れると、送ったスレッドが返事待ちになる。本文の末尾に「ご回答は11月10日（火）までにお願いいたします。」を入れるかを選べる（既定は入れる）。送る前の確認に、期限と本文が出る |
| 受け取ったメールを開く | 「期限」の欄で、対応期限を付ける・変える・外す。回答期限は受け取ったメールには付かない（委員会が送ったメールにだけ付く） |
| 送ったメールを開く | 「期限」の欄で、対応期限と回答期限を付ける・変える・外す。返事待ちを外すこともできる（相手の返信が届くと自動で外れる） |
| 受信箱の一覧 | 「期限」で「返事待ち」「期限切れ」に絞り込む。「並べ順」で「期限の近い順」に並べる（2026-11-04 に「並び」から改名。タスクの画面と同じ言い方）。一覧の行には、返事待ち・対応期限の札が出る |
| ホーム | 「メールの期限」の欄に、返事待ちで期限を過ぎたもの（電話などで届いているかを確かめることを考える）と、対応期限が近い（3 日以内）か過ぎたもの。返事待ちで期限を過ぎた件数は、上の「対応が必要な件数」にも「返事待ちで期限を過ぎたメール」として出て、押すとこの欄へ移る。委員会の受信箱でない構成（`/api/mail/due` が無い）では、欄ごと出さない |
| 履歴 | 期限の付与・変更・解除を、メールの「変更履歴」に残す。自動で外れたときは「自動（返信の受信）」と出る |

## 2. 返事待ちの規則

### 付く

- メールを送るとき、「回答期限」を入れて送った。送ったメールに、その日付の返事待ちが付く（送信が受け付けられた後）。
- 送ったメールの期限の欄で、回答期限を入れた（電話で話したあとに付け直すなど）。受け取ったメールには付かない。

回答期限は今日（日本時間）以降の実在する日付だけ付けられます。過去の日付は付けられません（既に付いている回答期限を、ほかの期限と一緒に保存するときは、そのままでよい）。

### 外れる（自動）

次のすべてを満たすメールが届いたとき、そのスレッド内で、届いた返信より前に送られた（返事待ちが始まった）メールの返事待ちを外します。回答期限の日付は、この判定に使いません。

1. 届いたメールが、同じスレッドに入る（References か In-Reply-To で、送ったメールにつながる）。
2. 新しく保存されたメールである（同じメールの写しが別の受信箱につながっただけのものは対象外）。
3. 差出人が委員会のドメイン（`domainAliases` の別名を含む）のアドレスではない。委員会のドメインのアドレス（委員のアドレスを含む）からの返信は、相手の返信とは扱わない。
4. 届いた日時が、返事待ちが始まった日時と同じか後である。過去の分の送り込みで、古いメールが届いても外れない。

外れたときは、履歴に「自動（返信の受信）」として残します。

既知の限界：

- 不在通知や自動返信も「返信」として外れる。
- 返信に References と In-Reply-To が無い（件名だけで返ってきた）メールは、同じスレッドにならないので外れない。
- 返事待ちが始まる前に届いていた返信では外れない。
- 委員が委員会のドメイン以外（個人の Gmail など）のアドレスから返信すると、相手の返信として外れる。判定に委員の登録アドレスは使っていない。直すかどうかは委員長の確認待ち。
- 同じ送信の答えを取り直したとき（送信の画面の再送など）は、返事待ちが付いているかだけを見る。付けられなかった回答期限については、そこでは何も答えない（「付いていない」とも言わない。画面の「期限」から付け直す）。

### 外す

期限の欄で、回答期限を空にして保存する。

## 3. 権限

| 操作 | 必要な権限 |
|---|---|
| 一覧・ホーム・スレッドの閲覧 | 委員会の Discord に参加している委員（これまでのメールと同じ） |
| 対応期限の付与・変更・解除 | そのメールが載っている受信箱の編集権限（メモと同じ。権限の管理者が付ける） |
| 回答期限の付与・変更・解除（送ったメールだけ） | 同上 |
| メールを送るときの回答期限 | その差出人の受信箱の送信権限と、同じ受信箱の編集権限 |

- 期限の欄は、編集権限がない人には読み取りだけ出る。付いている期限が無いメールでは、欄も出さない。
- 権限はサーバーで確かめる。画面に出ない操作も、直接の要求は同じ規則で拒否する。
- 送信の権限だけの人は、回答期限を付けられない。画面では欄を出さない。
- 同時の編集は版番号で守る。古い画面で保存すると 409（他の利用者が先に更新）になり、最新の期限を表示する。

## 4. データ

- 期限は `mail.sqlite3` の表 `message_due`（メッセージごとに 1 行）に保存する。対応期限・回答期限・返事待ちの開始時刻。
- 変更の履歴は既存の `history` 表に、`due`（対応期限）と `reply_wait`（回答期限・返事待ち）の行として残す。
- メールの保存先（`SMM_MAIL_DIR`）のバックアップに含まれる。
- 移行：表を追加するだけ（`CREATE TABLE IF NOT EXISTS`）。既存の表の列は変えず、`meta` の版（`1`）も変えない。期限の機能より前の版のアプリも同じファイルを開ける。
- 期限の判定は、日本時間の日付で行う（`app/src/shared/mailDue.ts` の `jstDay`）。

## 5. 有効にする方法

設定は要りません。委員会のメール（`SMM_AUTH_MODE=discord` と `SMM_MAIL_DIR`）が動いていれば使えます。送信の期限は、送信の設定（`mailbox.json` の `send`）があるときだけ出ます。

## 6. 実装の場所

- 規則と保存：`app/src/server/mailbox/due.ts`
- 日付と文言（画面とサーバーで共有）：`app/src/shared/mailDue.ts`

- 送信時の返事待ち：`app/src/server/mailbox/send.ts`（`startReplyWait`）
- API：`app/src/server/mailbox/routes.ts`（`PATCH /api/receipts/:receiptId/due`、`GET /api/mail/due`、一覧の `due`・`sort` の指定）

## 8. 残り

- デモモード（`SMM_AUTH_MODE=demo`）には委員会のメールの仕組みがないため、この機能はデモでは動かない。合成データの試験は、取り込みと同じ経路（署名付きの取り込み）で作っている。デモに出すには、デモ側へ委員会のメールを載せる別の作業が要る。
- 期限を過ぎたことを知らせる通知（Discord・メール）はない。ホームと一覧で見るだけ。
- 公式 LINE の会話には期限を付けない。
- 返事待ちは、スレッドの返信で外れる規則だけ。電話などで相手が返事をくれた場合は、手で外す。
- 期限の文言は固定（「ご回答は…までにお願いいたします。」）。文面の変更は画面のコードを直す。
- E2E（`tests/e2e`）は、このメールの期限の変更を含めて未実行。統合の時にまとめて回し、`.handling` の中の期限の欄が 320px で横にはみ出さないことも確かめる。
- 判定に委員の登録アドレスを使うかどうかは、委員長の確認待ち（既知の限界に書いたとおり、今は委員会のドメインだけで判定する）。

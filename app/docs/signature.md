# メールと公式LINE の署名（2026-11-10）

メールと公式LINE の送信画面は、本文の最後に委員会の署名を最初から入れておきます。署名は本文の一部なので、送る前に書き換えたり消したりできます。

## 形

メールは、委員会のメールで 2026 年 4〜11 月にいちばん多く使われていた形です。

```
ーーー ーーー ーーー ーーー ーーー ーーー ーーー ーーー
送信者

<委員会の名前>
<肩書き> <氏名>

<住所の行>
団体代表email : <委員会の窓口のアドレス>
委員個人email : <本人のアドレス>
ーーー ーーー ーーー ーーー ーーー ーーー ーーー ーーー
```

公式LINE は短い形です（本文のあと）。

```
ーーー
<委員会の名前>
<肩書き> <氏名>
```

- 委員会の名前は、メールの送信設定の差出人の名前（`send.fromName`）です。
- 肩書きは、本人が **設定 › 自分の設定 › 署名** で書いたもの。書いていなければ、Discord の部局から作ります（役員会は除き、課があれば課。例：「総務部・会計課」→「会計課」）。部局が無ければ氏名だけ。
- 本人のアドレスは、本人が同じ画面で書いたもの。無ければ「委員個人email」の行を出しません。
- 住所の行と委員会の窓口のアドレスは、権限管理者が同じ画面の「委員会の行」で書きます。どちらも無ければ、その段を出しません。
- 実際の住所・アドレスはこのリポジトリに書きません（公開リポジトリのため）。

## 送信画面での扱い

- メールの返信・新しいメールは、署名の入った本文から始まります。差出人（From）を変えても署名は変わりません（前の版は差出人の受信箱の名前とアドレスを入れていました）。
- Bot に頼んだメールの草案は、草案の終わりの署名の枠（委員会の名前が入った、罫線で囲んだ段）を委員会の署名に置き換えます。枠が無く委員会の名前も無い草案には、本文のあとに署名を足します。
- 送信前のチェックは、この罫線から下を署名として扱います（宛名・本文の量の確認は罫線より上で見ます）。
- Bot に校閲を頼むときは、本文の中のメールアドレスを「（メールアドレス）」に置き換えてから渡します。
- 公式LINE は、署名だけで本文が無いときは「本文を入力してください。」と出します。保存済みの返信の下書きがある会話では、署名を足しません。

## 置き場所と API

- `SMM_MAIL_DIR/signatures.json`（`iyakusai-signatures` の形式）。読めないファイルは書き換えず、署名の設定だけを止めて起動します（API は 503）。そのときの送信画面は、委員会の名前と氏名だけの署名になります。バックアップ（`ops/backup.ts`）に入ります。
- `GET /api/signature`：署名の材料と、設定の画面が表示するもの（ログインした委員）。
- `PUT /api/signature`：本人の肩書きと本人のアドレス（`{"title": "", "personalEmail": ""}`。両方空なら記録を消し、部局からの肩書きに戻る）。
- `PUT /api/signature/committee`：住所の行と窓口のアドレス（権限管理者だけ）。
- `GET /api/mail/send/options` の `signature` に、送信画面が使う材料が入ります。

## 前の版に戻すとき

前の版は `signatures.json` を読まないので、署名は前の形（`--`・差出人の名前・受信箱の名前とアドレス・氏名）に戻ります。`signatures.json` は残り、この版に戻すとまた使われます。

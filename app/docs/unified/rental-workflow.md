# 物品管理の段階操作と写真要件（2026-10-15）

物品を読むと現状サマリを表示し、貸出可能なら貸出へ、貸出中なら返却・随時チェックの選択へ進みます。選んだだけでは台帳に登録しません。物品状態による自動切替は、保存済みの auto_mode_20261015_af3f95082efc を統合しました。

貸出・返却・チェック記録の入力は、破損あり/なし → 写真 → メモ → 内容確認 → 登録結果の順です。各段階は戻れるため、写真とメモを保持して確認し直せます。予定貸出先は確認画面で変更できます。

学外物品はすべての操作で写真を1枚以上、最大5枚要求します。学内・委員会物品の写真は任意です。破損ありなら貸出・返却・チェックともメモ必須、破損なしなら任意です。サーバーも同じ条件を検証します。区分未設定の旧物品は新画面で登録を止め、管理者に区分の登録を求めます。旧端末からの未送信操作については、未区分の旧台帳に従来の写真ルールを残し、処理IDが一致する受付済み操作は新要件によらず重複受付の結果を返します。

随時チェックは今回の破損・写真・メモを独立した操作履歴に保存します。物品の貸出状態、借用団体、元の貸出メモ・写真、貸出数量を変更しません。同時更新を検出するため、個体の版だけを進めます。貸出時の状態と最新のチェック記録は現状サマリから確認できます。チェックの写真・記録は既存のDrive保存キューにも載ります。

ボタンや入力の近くに結果・エラーを表示します。選択は押下状態と結果文、写真追加は枚数、再送は開始結果を表示します。登録結果は、端末への保存・通信失敗・サーバー受付を区別します。受付前に貸出/返却完了と表示せず、失敗した写真とメモは端末に保持します。共通の権限管理とカード発行履歴は継続します。

データベースに items.photo_required を追加します。確認済みの学外は1、学内・委員会は0、未設定はNULLです。カード台帳登録・更新時も区分から同じ値を保存します。既存の学外区分が付いた個体は起動時に写真要件が設定されるため、カードの再発行・No.変更・割当や台帳のリセットは不要です。

写真要件は、物品の台帳（表計算）の列で品目ごとに「必須・任意・学内/学外で変わる」を示す運用を想定しています。パイプ椅子やテントのように個体で変わるものは、個体ごとの既存区分で判定します。台帳の列は運用基準を示すためのもので、サーバーは個体ごとの区分を使って必須条件を強制します。

確認用画面のデータは合成データです。実カード、スマホ実機のカメラ/NFC、別PCのUSB読取は今回未確認です。

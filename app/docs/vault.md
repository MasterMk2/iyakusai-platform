# パスワード帳

委員会のアカウント（サーバーの管理画面、ドメイン、各サービスの管理者など）の ID とパスワードを、アプリの中に置くための機能です（2026-11-23）。
控えは紙に印刷して、封をした封筒で保管する前提です。

設定 →「パスワード帳」に出ます。出るのは、どれかの区分を見られる人と権限管理者だけです。サーバーに `vault.json` が無ければ、誰にも出ません。

## 区分と、見られる人

- 項目は**区分**に入れます（例：システム・会計）。区分を作る・名前を変える・消すのは権限管理者です。項目が残っている区分は消せません。
- 区分ごとに、**部局**と**人**に役割を付けます。両方に当たる人は、強いほうの役割になります。

| 役割 | できること |
|---|---|
| 見る | パスワード・メモの表示とコピー、紙への印刷、見られる人の一覧 |
| 編集する | 見る＋項目の追加・変更・削除、別の区分への移動（移す先でも「編集する」が要る） |
| 管理する | 編集する＋見られる人の付け外し、記録を見る |

- 区分を作った人は、その区分の最初の「管理する」になります。ほかの人に「管理する」を付けてから自分を外せます。
- 個人の指定で「管理する」を持つ人を、最低 1 人は残します（部局の指定の「管理する」だけにはできません）。
- 部局は Discord のロールで決まります。**その部局のロールを付けられた人は、すぐに開けるようになります**。ロールの名前を変えると、前の名前の指定は外れます。見られる人の画面に「いま開ける人」を名前で出します。
- 権限管理者は、メンバーでない区分の名前・見られる人・記録を見られますが、値（項目の名前・ID・パスワード・メモ）は見られません。値を見るには自分を見られる人に加えます（加えたことは記録に残ります）。
- 臨時スタッフと、委員として登録されていないアカウントは使えません。

## パスワードの入れ直し

- 項目の一覧・値の表示とコピー・印刷・項目の変更・見られる人の変更は、**その端末で直近 10 分以内にログインのパスワードを入れた人だけ**ができます（`vault.json` の `revealMinutes`。入れた時刻から数え、使っていても延びません）。
- 過ぎていたら、画面がパスワードを求めます（メールの入れ直しと同じ `/api/auth/reauth`）。委員カードでログインした端末は、最初に必ず求めます。
- 区分の名前と件数、見られる人の一覧、記録は、入れ直しなしで見られます。記録に項目の名前が出るのは、その区分のメンバーで、10 分以内にパスワードを入れた人にだけです。

## 画面

- 上に区分の切り替え（すべて・区分ごと）、その下に検索欄と項目の一覧。各項目に「パスワードをコピー」「表示」「変更」（編集する人だけ）。
- 一覧にはパスワードとメモを載せません。「表示」「コピー」を押したときに 1 件ずつ取り寄せ、サーバーはそのことを記録してから値を返します。
- コピーした値は 30 秒後にクリップボードから消します（ブラウザーが前にあるときだけ確実）。
- 5 分操作が無いとき、タブを隠したとき、設定のほかの項目を開いたとき、「閉じる」を押したときは、表示していた値と一覧を画面から消します。
- 項目を追加するときは「ランダムに作る」で 20 文字のパスワードを作れます（見間違えやすい l・1・O・0 を使わない）。
- 変更の画面では、パスワードとメモは「変える」を押さない限りそのまま残ります。
- 項目の削除は戻せません。前の値はアプリに残さず、保存ファイルの中でも上書きします（`secure_delete`）。それより前に取ったバックアップには残ります。戻すときは紙の控えかバックアップから。
- 新しいパスワードの欄は、伏せ字で表示する文字の欄です（`type=password` にすると、ブラウザーが委員会のパスワードを個人のブラウザーに保存しようとするため）。伏せ字にできないブラウザーでは、入力した文字がそのまま見えます。
- 記録・印刷のボタンは、パスワード帳を開いているあいだだけ出ます。

## 紙の控え

- 区分を選んで「紙に印刷」。確認のあと、ブラウザーの印刷の画面が開きます。紙だけに出し、印刷が終わると画面から消えます。サーバーでは PDF を作りません。
- 紙には、区分の名前・**版**（項目の状態から作る 6 文字）・印刷日時・印刷した人・全項目（名前・URL・ID・パスワード・メモ・更新日）と、封筒の扱いを刷ります。
  - 封筒の表に、区分の名前・版・印刷日・封をした人の署名を書く。封に日付と署名を書いて、決めてある金庫へ（場所は実施手順書。このリポジトリには書かない）。
  - 開けたら、開けた人・日時・理由を記録して封をし直す。新しい版の紙を入れたら、古い紙は細断する。
- 印刷のあとに項目が変わると、区分の欄に「紙の控えが古くなっています（N 件の変更）」と出ます（区分の切り替えにも印が付きます）。
- 印刷の画面で「PDF に保存」を選ぶと、パスワードの入ったファイルが残ります。プリンターで印刷してください（画面では止めきれません）。

## 記録

区分ごとに、値の表示・コピー・印刷、項目の追加・変更・削除、区分と見られる人の変更を、誰がいつしたかを残します。値は残しません（変更は「パスワード」「名前」のように、変えた欄の名前だけ）。見られるのは、その区分の「管理する」人と権限管理者です。

## 保存と鍵

- 保存は `vault.sqlite3`（委員会のメールの保存先 `SMM_MAIL_DIR` の中。デモではデモのデータの隣）。
- 項目は名前・URL・ID・パスワード・メモの全部を AES-256-GCM で暗号化します。鍵は `vault.json` の `keyFile`（設定フォルダ）から作り、項目ごとに区分と項目の番号を付加データに入れます（行を別の区分へ移しても開けない）。
- 暗号化しないのは、区分の名前と説明、見られる人、項目の番号・区分・更新日時・更新した人、記録です。
- アプリのバックアップ（`dist/server/ops/backup.js`）は `mailbox/vault.sqlite3` を暗号文のまま写し、4 つの表の件数を `manifest.json` に書きます。鍵は写しません。
- **鍵がサーバーにあるので、サーバーを乗っ取られると中身はすべて読めます。** 鍵と `vault.sqlite3` が一緒に写った写しからも読めます。置き方は [docs/deployment.md](../../docs/deployment.md) の「パスワード帳」。
- 開けない項目（鍵が替わった、ファイルが変わった）は一覧から外し、「開けない項目が N 件」と出します。
- 応答はキャッシュさせず、アプリはログを出しません。Bot のデータソースには載せません。

## API

すべて `/api/vault`。ログインが要ります。無効のサーバーでは `meta` だけが答えます（`enabled: false`）。見られない区分・項目は `404` です。

| 経路 | 内容 | 入れ直し |
|---|---|---|
| `GET /meta` | 使えるか、権限管理者か、入れ直しの分数、いつまで開けるか | 不要 |
| `GET /sections` | 見られる区分（権限管理者は全部）と件数・紙の状態 | 不要 |
| `POST /sections`・`PUT /sections/:id`・`DELETE /sections/:id` | 区分を作る・直す・消す（権限管理者） | 要 |
| `GET /sections/:id/members` | 見られる人・いま開ける人・選べる部局と人 | 不要 |
| `PUT /sections/:id/members` | 部局か人の役割を付ける・変える・外す（`role: null`） | 要 |
| `GET /sections/:id/events` | 記録（管理する人と権限管理者） | 不要 |
| `POST /sections/:id/print` | 区分の全項目（印刷用。記録する） | 要 |
| `GET /entries` | 見られる項目（名前・URL・ID だけ） | 要 |
| `POST /entries`・`PUT /entries/:id`・`DELETE /entries/:id` | 項目を足す・直す（`password`・`notes` が `null` ならそのまま）・消す | 要 |
| `POST /entries/:id/reveal` | パスワードかメモを 1 つ（記録してから返す） | 要 |

入れ直しが要るのに過ぎていると `401`（`error: "vault_reauth_required"`）。

## 決めていること・していないこと

- 区分の分け方と付ける部局・人は、画面で決めます（コードに固定しない）。
- 鍵のファイル（SSH の秘密鍵など）の添付、ワンタイムパスワード、Bot での知らせ、鍵の入れ替えの道具はまだありません。
- 年度の切り替え（[rollover.md](rollover.md)）では写しません。
- 前の版のアプリに戻しても、`vault.sqlite3` は読まれないだけで残ります。

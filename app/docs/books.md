# 会計（帳簿・立替精算）

委員会の帳簿を基盤で付けるための機能です（2026-11-05 から）。会計はこれまで弥生会計で付けていて、将来はスプレッドシートで管理します。移行の期間は、**基盤で記帳し、弥生へはファイルで送る**運用にします。弥生だけで付けた仕訳は基盤へ取り込み直せます。移行が終わったら弥生への書き出しを止めるだけで、基盤とスプレッドシートが残ります。

上の段に「会計」タブがあります（ホーム・タスク・物品貸出・メール・公式LINE・連絡先・会計・Bot・設定）。

実装は次の 3 か所です。

- `app/src/server/books/`：保存、API、弥生のファイル、スプレッドシート、デモ
- `app/src/shared/books.ts`：入力の検査、科目の種類、型
- `app/src/client/components/books/`：画面

## 1. できること

| 画面 | 中身 | 使える人 |
|---|---|---|
| 立替精算 | 委員が立て替えた分を申請する。使った日・金額・支払先・何に使ったか・部局を入れ、レシートや領収書の写真・PDF を付ける（5 枚まで）。一定額を超えるときは事前承認の欄が出る。自分の申請の状況を見られ、出し直し・取り下げもできる | 委員全員 |
| 立替精算（確認） | 確認待ち・返金待ち・返金済み/差し戻しの切り替え。確認では、科目を選んで「承認して帳簿に入れる」か、理由を書いて差し戻す。返金待ちは委員ごとにまとめて選び、返金した日と口座を入れて返金済みにする。承認と返金はどちらも取り消せる | 会計の確定 |
| 帳簿 | 年度の仕訳を新しい順に並べる。口座・科目・入金/出金で読める形にし、摘要・取引先・科目・金額・番号で探せる。開くと、借方・貸方、領収書、変更の記録が出る | 会計を見る |
| 記帳 | 支出・収入・口座の移動・振替の 4 つの形から選ぶ。借方・貸方は基盤が組む。直す、取り消す（理由つき）、取り消しを戻すことができ、続けて記帳できる | 会計の確定 |
| 入金から記帳 | 入金確認（[payments.md](payments.md)）で確定した入金のうち、まだ帳簿にないものを並べる。団体の種類ごとに決めた収入の科目で、まとめて収入として記帳する。弥生で入れた入金は「弥生で記帳済み」の印を付け、二重に入れない。入金確認で確定を外した入金が帳簿に残っていれば、警告を出す | 会計の確定 |
| 残高と予算 | 口座ごとの期首・入金・出金・残高と、科目ごとの予算と実績（差と割合）。予算は科目ごとに入れる | 見る：会計を見る、予算を入れる：会計の確定 |
| 入金確認 | 入金確認の画面を、会計タブの中にそのまま出す（連絡先 → 団体 → 会計の入口も残す） | 会計を見る |
| 弥生 | 書き出し：まだ送っていない仕訳を弥生インポート形式のファイルにする。書き出したあとで直した仕訳は「弥生で手で直す」に出す。取り込み：弥生の仕訳・期首残高のファイルを下見してから取り込む | 会計の確定 |
| 科目と設定 | スプレッドシートの状態と「今すぐ書き込む」、記帳の決まり（年度の始まり・立替金の科目・入金の口座・団体の種類ごとの収入の科目）、科目（弥生の勘定科目・補助科目と同じ名前）、期首残高 | 見る：会計を見る、変える：会計の確定 |

画面の切り替えの数字は、会計課が片付けることの件数です。

- 立替精算：確認待ちの申請
- 帳簿：記帳する入金
- 弥生：まだ書き出していない仕訳と、弥生で直す仕訳

## 2. 使い方

1. **使い始め（会計課）**：
   - 「弥生」で、弥生の期首残高のファイルと仕訳のファイルを取り込む。弥生の科目もそのまま入る。
   - 弥生から始めないときは、「科目と設定」の「弥生の一般的な科目をまとめて足す」を使う。
   - 「科目と設定」の「記帳の決まり」で、立替金の科目（委員会の弥生では「立替金」）と入金の口座を決める。立替金の科目を決めるまで、立替精算は承認できない。
2. **立替精算（委員）**：会計 →「立替精算を申請する」→ 金額などを入れて写真を付ける →「申請する」。
3. **確認と返金（会計課）**：
   - 「確認待ち」で申請を開き、領収書を確かめて科目を選び、「承認して帳簿に入れる」を押す。帳簿には「借方 費用 / 貸方 立替金」が入る。
   - 「返金待ち」で返す申請を選び、日と口座を入れて返金済みにする。帳簿には「借方 立替金 / 貸方 口座」が入る。
4. **記帳（会計課）**：「帳簿」→「記帳する」→ 形を選び、日付・金額・口座・科目・摘要 →「記帳する」。
5. **弥生へ送る（移行の期間）**：
   - 「弥生」→「N 件を書き出す」→「ファイルを保存する」→ 弥生会計の仕訳のインポートで読み込む。
   - 書き出したあとで直した仕訳は、弥生でも手で直し、「弥生で直した」を押す。
6. **弥生だけで付けた分を戻す**：「弥生」→ 弥生から書き出したファイルを選ぶ →「下見を見る」→「N 件を取り込む」。
   - 基盤から書き出した仕訳は、摘要の `[KB J-000123]` で分かる。入れ直さず、弥生の伝票番号だけを控える。
   - すでに取り込んだ仕訳は、伝票番号と日付、伝票番号が無ければ中身で見分け、入れない。

スマホでも同じ手順で最後まで操作できます。

- 幅 900px 以下では、一覧と開いた項目が 1 列になる。
- 押すところは 44px 以上。
- 立替精算は、スマホでレシートを撮ってそのまま付けられる。

## 3. マスターシート（スプレッドシート）

帳簿の写しを、共有ドライブのスプレッドシートに書き込みます。委員が読む正本で、基盤が止まっても読めるように作ります。

- **委員は直接編集しない**：基盤が作ったタブを、基盤のサービスアカウントだけが編集できるよう保護する（警告だけの保護ではない）。各タブの説明には「直すときは基盤の『会計』から」と書く。
  - Google の仕様で、スプレッドシートのオーナー（共有ドライブでは管理者）は保護を外して書ける。それでも基盤のタブは書き込みのたびに全体を書き直すので、手で書いた分は次の書き込みで消える。
- **基盤が止まっても読める**：
  - どのタブも単独で読める。見出しは日本語、1 件 1 行で、上の行と同じ値も省かない。
  - 金額は数値（`#,##0`）、日付は日付の値（`yyyy-mm-dd`）。内部の ID は出さない（番号 `J-000123`・`TK-2026-001` が鍵）。全年度を書く。
  - 先頭の「案内」タブに、各タブの説明・最終更新・年度の合計・仕訳帳の貸借の一致・「基盤が止まったら」（コピーを作って手で続ける方法）を書く。
- **タブ**：案内、収支一覧（1 件 1 行。まずはここ）、口座残高、予算と実績、立替精算、仕訳帳（弥生と同じ借方・貸方。弥生に同じ帳簿を作り直せる）、残高試算表、期首残高、科目、取り消した仕訳。
  - 取り消した仕訳は、合計を出すタブには入れない。
- **ほかのタブは触らない**：
  - 基盤が作ったタブには印（開発者メタデータ `iyakusai-books-tab`）を付ける。
  - 同じ名前で印の無いタブがあれば、上書きせずに止め、画面に「そのタブの名前を変えてください」と出す。
  - 委員が足したタブ（集計やグラフ）はそのまま残る。
- **書くとき**：
  - 帳簿が変わってから少し待ち（既定 30 秒）、まとめて書き直す。値は RAW で書く（`=` で始まる摘要も式にならない）。
  - 失敗したときは、通信の一時的な失敗なら少し待って、それ以外（権限・設定の誤りなど）は 10 分おきに試し直す。
  - 起動したときは、止まっていた間の変更を書く。
  - 状態（最後に書けた時刻・失敗の種類）は「科目と設定」に出る。鍵や応答の中身は記録しない。

## 4. 権限

サーバーで毎回確かめます。権限は入金確認と同じものを使います（設定 →「会計の権限」）。

| 権限 | できること |
|---|---|
| なし（委員） | 自分の立替精算の申請・直す・取り下げ・領収書の付け外し。ほかの人の申請と帳簿は見られない（API は 403） |
| 会計を見る（`accounting.view`） | 帳簿、残高と予算、すべての立替精算、領収書、設定、スプレッドシートの状態を見る |
| 会計の確定（`accounting.confirm`） | 上に加えて、記帳、立替精算の承認・差し戻し・返金、入金から記帳、弥生の書き出しと取り込み、予算、科目、期首残高、設定、「今すぐ書き込む」 |

- 臨時スタッフとログインしていない人は使えない（401/403）。
- 書き込みは版番号で守る。ほかの人が先に変えていたら 409 で止め、入力は残す。
- 同じ「申請する」「記帳する」を 2 回送っても、1 件しか作らない（`clientToken`）。

## 5. データの置き場所

- `SMM_MAIL_DIR` の `books.sqlite3`（`payments.sqlite3` の隣）。
  - テーブル：`accounts`（科目）、`journals`・`lines`（仕訳と明細）、`claims`（立替精算）、`receipts`（領収書の記録）、`budgets`、`openings`（期首残高）、`deposit_links`（入金確認の入金との対応）、`yayoi_exports`（書き出したファイルそのもの。もう一度保存できる）、`yayoi_imports`、`settings`、`history`、`meta`。
- 領収書のファイルは `books-receipts/` に置く。中身の形式（JPEG・PNG・WebP・PDF）は先頭のバイトで確かめる。開くときは `nosniff` と `sandbox` を付けて返す。
- 統合アプリのバックアップ（`ops/backup.ts`）に含める。整合性の確認と件数を `manifest.json` に記録し、領収書は SHA-256 を照らしてから写す。
- 金額・名前・領収書はサーバーのログに出さない。
- **領収書はスプレッドシートには載らない**（枚数だけ）。基盤とそのバックアップにだけある。

## 6. 有効にする方法

- 運用（`SMM_AUTH_MODE=discord`）：委員会の受信箱を設定していれば、会計タブはそのまま使える。`books.sqlite3` を開けないときは、会計の API だけが 503 を返す。
- スプレッドシートは、`books-sheets.json` を `mailbox.json` と同じフォルダに置いたときだけ書く（無ければ書かずに動く）。手順は [deployment.md](../../docs/deployment.md) §4。
- デモ（`SMM_AUTH_MODE=demo`）：合成データの帳簿を作る。デモの人物では、「編集担当C」が会計の確定、「閲覧担当B」が会計を見る権限を持ち、ほかは立替精算だけを使える。デモではスプレッドシートに書かない。

## 7. 設計の判断

- **基盤を入口にした**（2026-11-05 委員長）。
  - 委員は単式の形（支出・収入・口座の移動）で入れ、借方・貸方は基盤が組む。
  - 弥生は書き出したファイルで追いかけ、移行が終わったら書き出しを止めるだけにする。
  - 弥生だけで付けた分は取り込み、重複は伝票番号と日付、伝票番号が無ければ中身で見分ける。
- **弥生のファイルの形式**：弥生インポート形式（27 項目、ヘッダーなし、Shift_JIS、CRLF）。
  - 1 仕訳 1 行は識別フラグ 2000。複数行は 2110…2100…2101。
  - 科目と補助科目は、弥生と一字一句同じ名前で合わせる（前後の空白も変えない）。
  - Shift_JIS で書けない文字は、書き出しの前に仕訳の番号と場所を示して止める。
- **一度書き出した仕訳は二度と書き出さない**。直したら「弥生で手で直す」に出す（同じ仕訳が弥生に 2 回入らないように）。
- **立替精算は 2 段で記帳する**：承認で「費用 / 立替金」、返金で「立替金 / 口座」。返金待ちの額が立替金の残高と一致する。承認や返金を取り消すと、その仕訳も取り消す。
- **入金確認とは記録でつなぐ**：入金ごとに 1 つの仕訳か「別に記帳済み」の印を持つ（`deposit_links`）。入金確認の側は変えない。
- **取り消しは消さない**：取り消した仕訳は印を付けて残し、合計には入れない。
- **期首残高は貸借が合うときだけ保存する**（取り込みと手入力の両方）。
- **新しい SQLite を 1 つ足した**：帳簿と領収書は機微なので、権限とバックアップを分けて確かめやすくするため。
- **新しいタブ「会計」を足した**：立替精算は委員全員が使うため、連絡先の中ではなく上の段に置いた。

## 8. 試したこと

`app/tests/contacts/`（すべて合成データ。外部へは送らない）:

- `books-http.test.ts`：
  - 権限：委員は申請だけ、会計を見る・会計の確定、臨時スタッフとログインなし。
  - 記帳と取り消し、立替精算の申請（領収書つき）から承認・返金までと仕訳、立替金の科目が未設定のときの承認の拒否と差し戻し。
  - 弥生の書き出し：1 回だけ・Shift_JIS・27 項目。
  - 弥生の取り込み：自分の書き出しは二重に入らない、弥生で変わった仕訳、古い下見は 409。
  - 期首残高：貸借が合わない取り込みと手入力は 422。
  - 入金確認の入金の記帳と「別に記帳済み」、予算と実績。
  - スプレッドシート：保護がサービスアカウントだけ・警告だけでないこと、日付と金額が数値、数式にならないこと、鍵が送られないこと、印の無い同じ名前のタブで止まること。
  - デモ。
- `books-files.test.ts`：
  - 弥生のファイル：1 行・複数行、引用符を含む摘要の往復、伝票番号と中身の鍵、読めない行と理由、和暦を含む日付、Shift_JIS で書けない文字、期首残高。
  - スプレッドシートのタブ：並び、案内、1 件 1 行、仕訳帳の貸借の一致、試算表と口座残高の一致、内部 ID が無いこと、取り消した仕訳の扱い。

弥生会計 Next から書き出した委員会の実データ（仕訳と期首残高）でも、読み込みと書き出しが一字一句一致することを手元で確かめました。実データはリポジトリに入れていません。

画面は、デモのサーバーを Playwright の Chromium で開いて確かめました（幅 1280px と 375px）。

- 記帳、続けて記帳、金額の入れ忘れの表示、取り消しと戻し、検索と 0 件
- 立替精算の承認と返金、委員の人物で写真つきの申請
- 予算の保存、弥生の書き出しとファイルの中身（27 項目）、そのファイルの取り込みの下見が「取り込む仕訳 0 件」になること
- 貸借が合わない期首残高を保存できないこと、科目の追加
- 入金確認の埋め込み、キーボードで画面を切り替えると URL も変わること
- スマホ幅で一覧と詳細が入れ替わること
- 計測スクリプトでの確認：小さすぎる押し領域・名前の無いボタン・ラベルの無い入力・コントラスト不足・横のはみ出しが 0

## 9. 残り（未実装・未確認）

- **本番には出していない**（委員長の判断待ち）。
- スプレッドシートへの書き込みは、Google の実際の API では試していない（試験は Google の応答を模したもの）。共有ドライブのファイルにサービスアカウントを編集者として足せるかは、Workspace の外部共有の設定によって変わる（未確認）。
- 領収書をドライブにも写すこと（基盤が無くなっても領収書を見られるように）はしていない。

- 予算は年度ごと・科目ごと（部局ごとの予算はない）。
- 消費税の計算はしない（税区分は弥生の値をそのまま持って返すだけ）。
- E2E の試験（Playwright の試験ファイル）は足していない（HTTP の試験とデモでの描画で確かめた）。

# 当日の画面（当日の欄）

医薬祭の当日に、本部からの連絡・その場で決めたこと・決め方・今日の予定・物品の状況を 1 か所で見るための欄です（2026-11-03）。
権限の管理者が決めた期間（日本時間）のあいだだけ、ホームのいちばん上に「当日」の欄が出ます。期間の外では何も出ません。

上のタブは増やしていません。入口はホーム（当日の欄）と設定タブ（期間・決め方・発信者）、物品貸出の画面（本部からの連絡）だけです。

## できること

- **当日モード**：設定タブの「当日の欄」で、権限の管理者が開始日と終了日を決める（両端の日を含む・最長 14 日）。期間のあいだだけ、ホームの先頭に「当日」の欄が出る。何日目か（例：1日目／2日間）も出る。期間の外のホームはこれまでと同じ（カードの順も変えていない）。
- **決め方の掲示**：管理者が書いた文（改行だけ使える。800 字まで）を、欄のいちばん上に出す。太字や箇条書きの記号は、そのまま文字として出る。
- **本部からの連絡（連絡板）**
  - 1 件ごとに、短い本文（300 字・8 行まで）、重要度（通常・重要・至急）、時刻、発信者、場所（任意）、部局（任意）を持つ。
  - 並び：未解決の**至急を先頭に固定**し、そのあとは新しい順（重要と通常は時刻の順で、重要度では並べ替えない）。前の日の未解決の連絡は期間の終わりまで残り、時刻の前に日付（例：11/3 23:51）が付く（期間は最長 14 日なので年は付けない）。**期間の開始日より前に書いた連絡（試しに設定した期間の連絡や、去年の当日の連絡）は、未解決のままでも出さない**（データには残る。下の「期間の外の連絡」）。
  - 対応が済んだ連絡は「済」にでき、欄の下の「今日済んだ連絡（N 件）」に畳まれる。「未解決に戻す」で戻せる。前の日に済んだ連絡は出ない。
  - 書いた人と権限の管理者は、本文を直せる（「直しあり」と出る。物品貸出の画面でも同じ言い方）・取り下げられる。取り下げた連絡は消えず、発信者だけに「今日取り下げた連絡」として出て、「戻す」で戻せる。
  - **直しているあいだにほかの人が同じ連絡を変えたとき**：直す欄は「直す」を押した時点の版で保存する（30 秒ごとの読み直しで版を進めない）。そのため、ほかの人の直しを黙って上書きすることはない（サーバーが `409` で断る）。読み直しで変更が分かると、直す欄の上に「直しているあいだに、ほかの人がこの連絡を変更しました」といまの内容が出て、書きかけの文はそのまま残る。「いまの内容に入れ替える」か「自分の文で上書きして保存」を選ぶまで、ふつうの保存は押せない。保存したときに断られた場合も、読み直してから同じ表示になる。ほかの人が済にした・取り下げたときは、直す欄を消さずに「この連絡はもう直せません」と出し、書きかけの文を残す（写してから「やめる」）。
  - 済・取り下げのあとに出る「元に戻す」で、すぐに取り消せる（確認のダイアログは出さない）。
  - 「臨時スタッフにも見せる」を付けた連絡だけが、臨時スタッフに見える（下の「臨時スタッフに見せる範囲」）。
- **その場で決めたこと**：「決めたことを記録」から、決めたこと（1 行）・関係する場所や人（任意）・部局（1 つ以上）だけを入れると、**決定事項の台帳**（[decisions.md](decisions.md)）に、決めた日＝今日（日本時間）・決めた場＝「当日本部」で入る。欄には今日の決定が新しい順に出て、題の下に台帳の本文の 1 行目（当日の欄から入れたものは「関係する場所・人：…」。60 字で切る）が出る。題をクリックすると台帳の詳細が開く。直す・変更として登録・取り消しは台帳の画面で、台帳の決まりどおりに行う。
- **今日の予定**：委員会カレンダー（[calendar.md](calendar.md)）の今日の予定（毎年の予定を含む）を時刻順に出す。「カレンダーで見る」でカレンダーの今日を開く。
- **物品の状況**：物品の権限（貸出か発行）がある人にだけ、貸出中の数（カードの物品の件数・数の物品の個数）と、回収が済んでいない団体の数を出す。「物品貸出を開く」「団体の回収表を開く」で物品の画面へ。物品貸出を止めている間（設定 › 使う機能、2026-11-09）は出さない。
- **更新**：欄は画面に出ているあいだ 30 秒ごとに読み直す。期間の外でも、ホームを開いているあいだは 5 分ごとに読み直す（前の日から開いたままの本部の端末でも、0:00 JST を過ぎるか管理者が期間を保存すると、5 分以内に欄が出る）。タブを隠すと止まり、戻すとすぐに読み直す。
- **新着の印は至急だけ**：前回から増えた至急の連絡（新しく書かれたもの・至急に直されたもの・未解決に戻されたもの）があると、欄の上に「新しい至急の連絡が N 件あります」（見る／確認した）が出て、その連絡に「新着」の印と枠が付く。印と知らせは「確認した」で消える。通常・重要の新しい連絡には印を付けない（一日開いたままの画面で、すべてに印が付いたまま消えなくなるため）。最初に開いたときは印を付けない（全部が初めて見るものなので）。
- **読み込み中**：このタブで今日すでに当日の欄を出していれば、次にホームを開いたときは、読み込みが終わるまで前回の高さの枠（「当日の欄を読み込んでいます…」）を出す。読み込みのあとに欄が割り込んで、下の「対応が必要な件数」やカードが押し下げられないようにするため。タブに残すのは今日の日付と高さだけ（`sessionStorage`。連絡の中身は残さない）。そのタブで今日初めて開いたときは枠がなく、読み込みのあとに欄が出る。
- **物品貸出の画面**：ログインした人には、物品貸出の画面（`/rental`）の上に「本部からの連絡」が出る。至急は開いたまま、ほかは畳む（至急があるときは「ほかの連絡 N 件」、ないときは「連絡 N 件（重要 1・通常 2）」のように、実際にある重要度だけを出す）。読むだけで、書く・済にする操作はない。連絡が 1 件もないときと期間の外は出ない。30 秒ごとの読み直しで連絡が変わらないときは「◯時点」の時刻だけを変え、変わったときだけ作り直す（畳んだ行にフォーカスがあれば、作り直したあとも戻す）。新しい至急の読み上げは、箱の外に 1 つだけ置いた読み上げの行で知らせる。

## 使い方

1. **管理者（期間・決め方・発信者）**：設定タブ →「当日の欄」。
   - 開始日と終了日、決め方の文を入れて「期間と決め方を保存」。期間をやめるときは両方の日付を空にして保存する（連絡や記録は消えない）。
   - 「当日の発信者」で、書ける人を部局ごと（ロールの部局名）か委員ごとに選ぶ。チェックはその場で保存される。部局で付けた人は、委員ごとの欄に「部局」と出る。
2. **発信者（本部）**：ホームの当日の欄 →「連絡を書く」→ 本文・重要度・場所・部局を入れて「本部から流す」。対応が済んだら「済にする」。
3. **委員**：ホームの当日の欄を見る。その場で決めたことは「決めたことを記録」→「台帳に記録する」。
4. **臨時スタッフ**：物品貸出の画面の上の「本部からの連絡」を見る。

## 臨時スタッフに見せる範囲

臨時スタッフ（ログイン ID が臨時スタッフの範囲・ロールが「臨時スタッフ」・臨時スタッフのセッション）に見せるのは、次だけです。

| 見せるもの | 見せないもの |
|---|---|
| 発信者が「臨時スタッフにも見せる」を付けた、**未解決**の連絡の本文・重要度・時刻・場所・部局 | 付けていない連絡、済んだ連絡、取り下げた連絡 |
| 発信者は「本部」とだけ出す（委員の名前は出さない） | 発信者・済にした人の名前 |
| | 決め方の文、今日決めたこと（台帳）、今日の予定、物品の数、期間の設定、発信者の一覧 |

「臨時スタッフにも見せる」は、連絡ごとに既定で**付いていない**（委員向けの連絡がうっかり外に出ないように）。臨時スタッフはホームの当日の欄（`/api/dayof/board`）を読めず（`403`）、Discord ログインの臨時スタッフの許可一覧にも `GET /api/dayof/notices` だけを足した。

## データの置き場所

- **本番**（受信箱（`SMM_MAIL_DIR`）を使う）：受信箱の保存先の `dayof.sqlite3`。決定事項の台帳（`decisions.sqlite3`）と同じフォルダで、受信箱のバックアップ（`app/src/server/ops/backup.ts`）に含まれる（`mailbox/dayof.sqlite3`。件数は `dayof.posts`・`dayof.post_history`・`dayof.poster_grants`・`dayof.admin_history`）。
- **デモ**（`SMM_AUTH_MODE=demo`）：データファイル（`SMM_DATA_FILE`）と同じフォルダの `dayof.sqlite3`。空のときだけ、合成の初期データ（今日から 2 日間の期間・決め方の例・至急／重要／通常の連絡・済んだ連絡・当日本部の決定 1 件・発信者に `u-editor-a`）が入る。連絡の時刻は今日の 0:00 JST より前にしない（深夜に起動しても欄に出るように）。デモのフォルダを残したまま期間が過ぎたときは、期間を今日からに移し（長さは同じ）、合成の連絡と決定を入れ直す（前の期間の連絡は欄に出ないため）。
- 中身：期間と決め方（1 行・版番号つき）、発信者（部局・委員）、連絡（版番号つき）、連絡の履歴（`post_history`。直す前の内容を `before_json` に残す）、設定と発信者の変更の記録（`admin_history`）。連絡は削除しない。
- その場で決めたことは `dayof.sqlite3` には入れず、決定事項の台帳（`decisions.sqlite3`）に入る。今日の予定はカレンダー（`calendar.sqlite3`）、物品の数は物品のデータから、そのつど読む。

## 権限

| 操作 | 誰ができるか |
|---|---|
| ホームの当日の欄を読む | ログインした委員全員（臨時スタッフ・無効なアカウントは不可） |
| 物品貸出の画面の「本部からの連絡」を読む | 委員全員（未解決の連絡すべて）と臨時スタッフ（上の範囲だけ） |
| 連絡を書く | 権限の管理者（いつも）と、管理者が選んだ発信者（委員ごと・部局ごと）。**既定では管理者だけ** |
| 済にする・未解決に戻す | 発信者全員（本部で分担して片付けるため） |
| 直す・取り下げる・戻す | その連絡を書いた人と権限の管理者（どちらも発信者であること） |
| その場で決めたことを記録 | 委員全員（決定事項の台帳の登録と同じ。臨時スタッフは不可） |
| 期間・決め方・発信者を変える | 権限の管理者（`canManageAccess`） |

権限はすべてサーバー側で確かめる（画面で隠すだけにしない）。部局は、メールの部局ごとの権限と同じく、ロールの名前（`roleLabel` を「・」で区切ったもの）で決まる。新しい連絡と決定の記録は期間の中だけ受け付ける（期間の外は `409`）。

### 期間の外の連絡

- 当日の欄と物品貸出の画面に出すのは、**今の期間の開始日（0:00 JST）以降に書いた連絡だけ**。試しに設定した期間や去年の当日に書いて未解決のまま残った連絡は、次の期間には出ない（至急として先頭に固定されたり、臨時スタッフの画面に出たりしない）。片付ける操作は要らない。
- そうした連絡は消さずに `dayof.sqlite3` に残る（未解決のまま）。画面には一覧がない。API（`PUT posts/:id`、`POST posts/:id/{resolve,…}`）は期間の外でも受け付けるが、画面からは期間中の欄でしか操作できない。
- 期間の途中で開始日を後ろにずらすと、新しい開始日より前に書いた未解決の連絡は欄から外れる（データには残る。開始日を戻せばまた出る）。

### API（すべて `/api/dayof/`）

| 経路 | 内容 |
|---|---|
| `GET board` | ホームの当日の欄。期間の外は `active: false` と期間だけ |
| `GET notices` | 連絡だけ（物品貸出の画面用）。臨時スタッフは上の範囲だけ |
| `POST posts` | 連絡を書く（`clientToken` で送り直しても 1 件） |
| `PUT posts/:id` | 直す（`expectedVersion`。古い版は `409`） |
| `POST posts/:id/{resolve,reopen,withdraw,restore}` | 済・未解決に戻す・取り下げ・戻す（`expectedVersion`） |
| `POST decisions` | その場で決めたことを台帳に記録（`clientToken` で送り直しても 1 件） |
| `GET admin`・`PUT admin/settings`・`PUT admin/posters` | 管理者の設定（期間と決め方は `expectedVersion`） |

受信箱もデモもない起動では、どの経路もない（`404`）。画面は `404` で欄と設定を出さない。

## 有効にする方法

- **本番**：受信箱（`SMM_MAIL_DIR`）を設定して起動すると、自動で使えるようになる。追加の環境変数はない。ただし**期間を決めるまで欄は出ない**（設定タブで管理者が期間を保存する）。
- **デモ**：`SMM_AUTH_MODE=demo` で起動すると、今日を含む合成の期間で欄が出る。
- 物品の状況は物品貸出（`SMM_RENTAL_DATA_DIR`）があるとき、今日の予定はカレンダー（受信箱かデモ）があるときだけ出る。
- 当日が終わったら、期間を空にするか、期間が過ぎるのを待つ（自動で出なくなる）。

## 決めたこと（前提）

- **決めた場の値**：台帳の決めた場は「その他」とし、名前に「当日本部」を入れた（台帳の決めた場の種類を増やすと、議事録からの登録の画面の決まった選択肢と合わなくなるため）。台帳の一覧の絞り込みでは「その他」に入る。詳細と当日の欄、Bot の口では「当日本部」と出る。
- **決定の記録は委員全員**：台帳と同じ決まりにした（発信者だけに絞らない）。決めた日はサーバーが日本時間の今日にする。
- **臨時スタッフ**：既定では連絡を見せない。見せる連絡でも名前は出さない。
- **済にするのは発信者全員**、直す・取り下げるのは書いた人と管理者。
- **期間は最長 14 日**、日付は日本時間で両端を含む（00:00 JST＝前日 15:00 UTC で切り替わる）。
- **更新の差分**：サーバーは毎回、今の連絡すべてと書き込みのたびに増える番号（`revision`）を返し、新しい至急の判定は画面で前回と比べて行う。
- 連絡は消さない（取り下げと戻すで取り消す）。
- **前の期間の連絡は持ち越さない**：期間の開始日より前に書いた連絡は欄に出さない（未解決でも）。片付けの画面を作るより、来年の当日や試しの期間のあとに古い至急が先頭に出ない仕組みのほうが確実なため。
- **新着の印は至急だけ**：仕様の「新しい至急の連絡が来たら目立たせる」に合わせた。通常・重要にも付けると、消す操作が別に要る。
- **直しの衝突**：直す欄を開いた時点の版で保存し、ほかの人の直しは黙って上書きしない。上書きは、いまの内容を見たうえで本人が選んだときだけ。
- **期間の外の読み直しは 5 分ごと**：物品貸出の画面の間隔（`IDLE_MS`）と同じ。期間の外の応答は期間だけなので軽い。
- **読み込み中の枠**：タブに残すのは今日の日付と高さだけ（共用の端末で別の人がログインしても、連絡の中身が出ないように）。

## 残り

- E2E の spec は足していない。デモのホームに当日の欄が出るようになるので、ホームの先頭の要素を前提にした E2E があれば影響を確かめる（ホームのカードの順は変えていない）。
- 設定タブを幅 375・320 で開くと横にはみ出す（デモ管理の権限表 `access-matrix` が原因で、当日の設定を出さなくても同じ。この変更より前からある）。
- デモの利用者の役割名（例：「編集者（サポート・営業）」）は「・」で区切ると部局の名前にならないため、デモでは連絡の部局の選択肢と発信者の部局が不自然な名前になる（メールの部局ごとの権限と同じ扱い。本番は Discord のロールの部局名）。
- 決めたことの部局は、タスクサービスの部局の名前が読めるときはその名前、読めないとき（デモなど）は台帳の部局キー（例：planning）のまま出る。
- 物品貸出の画面の連絡は、オフライン用のキャッシュ（`sw.js`）に入れていない（電波がないときは出ない。連絡は新しさが大事なため）。
- 通知（音・プッシュ）、連絡の検索、前の日の連絡の一覧、連絡ごとの履歴の画面はない（履歴は保存している）。
- 前の期間に未解決のまま残った連絡を見る・まとめて済にする画面はない（欄に出ないので困らない想定。必要なら設定の「当日の欄」に足す）。
- 直しの衝突の画面の動きは、単体の試験（版を決める関数）と HTTP の試験、手元のブラウザでの確認で押さえた。画面の E2E の spec は足していない（E2E は流さない決まりのため、通るか確かめられない spec は足さなかった）。
- 読み込み中の枠は、そのタブで今日 2 回目以降にホームを開いたときだけ出る（最初の 1 回は、読み込みのあとに欄が割り込む）。
- Bot には出していない（当日の決定は台帳経由で Bot の口に入る）。

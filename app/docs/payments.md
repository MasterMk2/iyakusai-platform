# 入金確認（会計）

会計課が、団体への請求と銀行の入金を照らし合わせて「入金済み」を確定する機能です。連絡先タブの「団体」の上にある「会計」から開きます（タブは増やしていません）。会計の権限がある人にだけ入口が出ます。

実装は `app/src/server/payments/`（保存・API・デモ）、`app/src/shared/payments.ts`（名前の正規化・候補の順位・明細の読み方・型）、`app/src/client/components/payments/`（画面）です。

## 1. できること

| 機能 | 中身 |
|---|---|
| 請求 | 団体ごとに、請求額・請求日・支払の期限・請求番号（空なら `2026-001` の形で自動）・振込名義（カナ）・メモ。団体の金額と、同じ団体名の以前の請求の振込名義（無ければ以前に確定した入金の摘要）から下書きする。版番号と記録つき。編集する・取り消す（理由つき。確定した入金があると取り消せない）・取り消しを戻す |
| 請求日の候補 | その団体に一斉送信でメールを送った日（件名に「請求」を含むものを先に）を、請求日の入力の下にボタンで出す。押したときだけ入る（自動では入れない） |
| 入出金明細の取り込み | 銀行の CSV（Shift_JIS・UTF-8。団体の取り込みと同じ `decodeCsvBytes`・`parseCsvRecords`）。見出しの行（上に口座の情報の行がある銀行向け）と列の対応を推定し、画面で変えられる。下見で、新しい入金・取り込み済み（日付・摘要・金額・残高が同じ）・出金・読めない行（理由つき）に分け、確かめてから取り込む。出金は保存しない |
| 照合の候補 | 請求ごとに、まだ請求に充てていない入金を並べる。金額（一致・振込手数料 990 円以内を引いた額・分割の一部・多い）と、振込人の名前の近さ（カナ・全角半角・小書き・（カ）（ユ）や「株式会社」などを除いて比べる）で順位を付け、理由を出す。入金の側からも、合う請求を並べる |
| 確定 | 確定の権限がある人が、入金を選んで「選んだ入金で確定」。1 つの入金は 1 つの請求にだけ充てる。1 つの請求に複数の入金（分割）は可。足りないときは、理由を書いて「不足を認めて入金済み」にできる（照合できていない入金が残っていない一部入金の請求でも出る。入金の側からは、振込手数料ぶん少ない候補に「不足を認めて確定…」）。多いときは過払いとして出す。確定の結果とエラーは、押したボタンのそば（確定の欄・押した行の下）に出す |
| 団体への反映 | 請求（取り消したものを除く）がすべて入金済みになると、団体の状態を「入金済み」に進め（協賛・出展団体のみ、前へだけ）、団体の履歴に「入金を確認」を残す。確認した人は履歴の行に出る。請求の編集（額の変更）・取り消し・取り消しを戻す・追加の請求の作成で「すべて入金済みか」が変わったときも、同じように進める・戻す（団体の履歴には「請求の変更を反映」。状態が動いたときだけ） |
| 確定を外す | 充てた入金ごとに「確定を外す」、不足を認めた請求は「不足の承認を取り消す」。記録は残る。団体の状態がまだ「入金済み」なら、進める前の状態に戻し、団体の履歴に「入金の確定を外す」を残す |
| 一覧 | 未入金（期限切れを先頭）・入金済み・照合できていない入金・過不足の 4 つを件数つきで切り替える。ほかに、照合の対象外にした入金（利息など。理由つき、戻せる）、取り消した請求、明細の取り込みの記録（確定した入金が無い取り込みは取り消せる） |
| CSV の書き出し | 年度の請求と入金（過払い・不足の列つき）、取り込んだ入金のすべて。UTF-8（BOM 付き）。会計を見る人だけ |
| 団体の詳細 | 団体の詳細に「入金」を出す。会計の権限がない委員には「入金済み」「未入金」だけ（金額・請求番号・振込人は出さない）。権限がある人には請求と充てた入金も出す。団体の履歴の入金の行も同じで、金額・入金日・請求番号は会計を見る権限がある人だけに出る（権限のない委員には、状態を動かした行だけが「入金を確認」などの名前で出る） |

## 2. 使い方

1. 連絡先タブ →「団体」→ 一覧の上の「会計」。
2. **請求を作る**：「請求を作る」→ 団体を選ぶ（金額と振込名義が入る）→ 請求日（メールを送った日のボタンを押してもよい）・支払の期限 →「請求を作る」。
3. **明細を取り込む**：ネットバンキングで入出金明細を CSV で保存 →「明細を取り込む」→ ファイルを選ぶ → 見出しの行と列を確かめる →「下見を見る」→「新しい入金 N 件を取り込む」。同じ明細を 2 回取り込んでも、取り込み済みの行は増えない。
4. **確定する**：「未入金」で請求を開く → 候補の入金の行を押して選ぶ（行のどこを押してもよい）→「選んだ入金で確定」。または「照合できていない入金」で入金を開き、合う請求の「この請求で確定」。
5. 間違えたら、請求の「この請求に充てた入金」の「確定を外す」。不足を認めたのを戻すときは「不足の承認を取り消す」。
6. 振込手数料を引かれて少ない入金は、請求の画面で入金を選び「不足 N 円を認めて入金済みにする」に印を付けて理由を書くか、入金の画面の「不足を認めて確定…」で理由を書いて確定する。ほかの入金をすべて照合し終えたあとでも、一部入金の請求の画面で同じように不足を認められる。

スマホでも同じ手順で最後まで操作できます（一覧と詳細は 900px 以下で 1 列。選ぶ行・確定・切り替えは 44px 以上）。

## 3. データの置き場所

- `SMM_MAIL_DIR`（メールの保存フォルダ）の `payments.sqlite3`。`contacts.sqlite3`・`organizations.sqlite3` の隣。独自のスキーマ版（`meta.schema = 1`）。
- テーブル：`invoices`（請求）、`imports`（明細の取り込み）、`deposits`（入金。重複の判定に使う鍵 `dup_key`、正規化した振込人 `payer_key`）、`allocations`（入金を請求に充てた記録。取り消しは `undone_at` を入れて残す。生きている行は入金ごとに 1 つだけという部分一意索引）、`history`（請求・入金・取り込みの記録）、`grants`・`department_grants`・`access_events`（会計の権限とその変更の記録）。
- 団体の状態と団体の履歴は `organizations.sqlite3` に書く（先に `payments.sqlite3` に確定を書き、そのあと団体を進める。団体を書けなかったときは画面に「団体の状態は変えられませんでした」と出る）。
- 統合アプリのバックアップ（`ops/backup.ts`）に含める。整合性の確認と件数（`payments.invoices`・`deposits`・`allocations`・`history`）を `manifest.json` に記録する。
- 金額・振込人の名前はサーバーのログに出さない。団体の履歴には振込人の名前を書かない（金額・入金日・請求番号・不足を認めたか・その時点の入金の累計・状態を動かした請求の変更の種類だけ）。それも API が返すのは会計を見る権限がある人にだけ（`/api/organizations/:id` の `history[].payment`。ほかの人には `null`）。

## 4. 権限

サーバーで毎回確かめます（入口を隠すだけにはしていません）。

| 権限 | できること |
|---|---|
| なし（委員） | 団体の詳細で「入金済み」「未入金」だけを見る。`/api/payments/organizations/:id` は `detail: null` を返す。団体の履歴の入金の行は、状態を動かしたものだけを `payment: null` で返す（金額・入金日・請求番号・回数は出さない）。ほかの会計の API は 403 |
| 会計を見る（`accounting.view`） | 一覧・請求と入金の詳細・CSV の書き出し |
| 請求と入金の確定（`accounting.confirm`） | 上に加えて、請求の作成・変更・取り消し、明細の取り込みと取り消し、入金の確定と取り消し、照合の対象外。確定できる人は見ることもできる |
| 権限管理者 | 設定 →「会計の権限」で、部局ごと（その Discord ロールを持つ委員全員。例：会計課）と委員ごとに付け外しする。権限管理者であることだけでは会計の権限は付かない |

- 臨時スタッフ（臨時スタッフのロール、臨時スタッフのログイン ID）は、権限を付けても会計を使えない（API は 403。設定の一覧にも出ない）。ログインしていない人は 401。
- 権限の変更は版（`revision`）で守る。ほかの管理者が先に変えていたら 409 で止め、読み直す。
- 請求の書き込みは版番号で守る。古い画面からの 2 回目の確定は 409（画面は最新を読み込み、まだ選べる入金だけを残す。外したときは「選んでいた入金のうち N 件は…外しました」と出す）。選んだ入金が、その間にほかの人の操作で照合の対象外になった・取り込みごと取り消されたときも 409 で、同じように読み直す。

## 5. 有効にする方法

- 運用：`SMM_AUTH_MODE=discord` で委員会の受信箱（`SMM_MAIL_DIR`・`SMM_MAIL_CONFIG`）を設定すると、連絡先・団体と同じく自動で使える（設定の追加は不要）。`payments.sqlite3` を開けないときは会計の API だけが 503 を返し、ほかは動く。
- 使い始めに、権限管理者が設定の「会計の権限」で、部局「会計課」に「請求と入金の確定」を付ける（または委員ごとに付ける）。
- デモ（`SMM_AUTH_MODE=demo`）：デモのデータファイルの隣に合成データの `contacts.sqlite3`・`organizations.sqlite3`・`payments.sqlite3` を作り、連絡先タブ（連絡先・団体・会計）を出す。デモの人物のうち「編集担当C」が確定、「閲覧担当B」が閲覧の権限を持つ。デモのメールはここでは使えない（一斉送信の入口は出ない）。

## 6. 設計の判断

- 新しい SQLite を 1 つ足した（明細は機微な情報なので、団体の台帳と分けて権限とバックアップを確かめやすくするため）。
- 重複の判定は「日付・摘要・金額・残高」が同じ行。残高の列が無い明細で同じ日に同じ人から同じ額が 2 回あるときは、同じファイルの中の n 件目までを別の入金として数える。
- 下見と取り込みは同じ行を送り、下見の要約（`planToken`）が一致するときだけ書く。下見のあとにほかの人が取り込んでいたら 409 で止める。
- 確定を外したときに団体の状態を戻すのは、まだ「入金済み」のときだけ（人がその後に「お礼状を送った」などへ進めていたら触らない）。戻す先は、会計が「入金済み」に進めたときに覚えた状態（`invoices.org_status_before`。最後に進めた 1 件だけが持つ）。人が手で「入金済み」にした団体は、戻す先を知らないので戻さない。
- 団体の状態は、確定・確定を外すのほか、請求の作成・編集・取り消し・取り消しを戻すのたびに「取り消していない請求がすべて入金済みか」で合わせ直す（2026-11-04。額を上げた入金済みの請求が「一部入金」に戻ったのに団体が「入金済み」のまま、二重に作った請求を取り消したのに団体が「請求済み」のまま、という食い違いを残さないため）。請求の変更では、状態が動いたときだけ団体の履歴に「請求の変更を反映」を書く（メモを直すたびに団体の履歴が増えないように）。
- 団体の履歴の入金の金額・入金日・請求番号は、会計を見る権限がない委員には返さない（2026-11-04。分割の入金では確定ごとに行が増え、入金ごとの額と日付が全委員に見えてしまうため）。権限のない委員には、状態を動かした行だけを出す（状態は団体の台帳としてもともと全委員が見る）。
- 不足の承認だけの確定（入金を選ばない）は、団体の履歴に「0 円の入金」ではなく「不足を認めて入金済み（入金 2,500円・最後の入金 日付）」と残す。不足の承認を取り消したときも同じ。
- 請求を作っても団体の状態を「請求済み」には進めない（「請求済み」にするかは渉外課・企画部が決める）。入金済みの団体に請求を足したときだけ、上のとおり「入金済み」から戻す。
- 画面の入口は団体の一覧の上の「会計」だけ（ホームのカードは足していない）。

## 8. 残り（未実装・未確認）

- 1 つの入金を複数の請求に分けて充てること（まとめて振り込まれた場合）はできない。必要なら、請求を 1 つにまとめるか、差額を過払い・不足として扱う。
- 同じ団体への 2 つ目の請求は API（`allowAnother`）だけで、画面の「請求を作る」は請求の無い団体だけを選べる。
- 会計の画面の状態（開いている一覧・請求）は URL に残らない。再読み込みすると団体の一覧に戻る。
- 請求書（PDF）の作成・送付は扱っていない（一斉送信の添付で送る）。
- 銀行の API からの自動取得はしない（CSV を手で取り込む）。
- 本番のデータ（実際の銀行の CSV の列名）では確かめていない。列の推定が外れたときは画面で選び直す。
- デモの設定画面の旧来の権限表（`AdminPanel` の表）は 375px・320px で横にはみ出す（この変更の前からのもの。会計の権限の欄ははみ出さない）。
- 人が手で「入金済み」にした団体は、請求が入金済みでなくなっても会計からは戻さない（戻す先を知らないため。団体の画面で直す）。
- 2026-11-04 に足した流れ（請求の変更での団体の合わせ直し、入金の側からの不足の承認、競合のあとの読み直し、権限の行ごとの保存）の E2E の試験は足していない（HTTP の試験とデモでの描画で確かめた）。

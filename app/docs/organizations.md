# 団体の台帳と一斉送信

協賛・寄付・出展団体・業者・大学の部署・その他の団体を、委員会で 1 つの台帳にまとめます。連絡先タブの中の「団体」に入っています（タブは増やしていません）。
協賛マスター（Excel の CSV）からの取り込みと、差し込みつきの一斉送信（請求書の案内など）もここから行います。

実装は `app/src/server/organizations/`（保存・API・送信の順序）、`app/src/shared/organizations.ts`（規則と型）、`app/src/client/components/organizations/`（画面）です。

## 1. できること

| 機能 | 中身 |
|---|---|
| 団体の台帳 | 団体名、種別、年度、委員会側の部局と担当（委員）、相手の担当者（連絡先と結ぶ）、状態、金額、協賛の内容、次の対応と期限、メモ。版番号と履歴つき。同じ団体名と年度は 1 つだけ（作成・改名は 409 で止める） |
| 状態 | 協賛：依頼前 → 依頼済み → 申込を受けた → 請求済み → 入金済み → お礼状を送った。出展団体：申込 → 書類確認 → 請求済み → 入金済み → 当日 → 完了。ほかの種別は自由な短い文字 |
| 状態を進める | 協賛と出展団体は、詳細の「状態を変える」で選ぶとすぐ保存する（版が違えば止めて、最新を読み込める） |
| 一覧 | 年度・種別・委員会側の担当・部局で絞る、状態ごとの件数で絞る、団体名・部局・内容・メモで探す。ページ送り。期限が過ぎたものは赤、1 週間以内は黄 |
| 詳細 | 中身の確認、編集、変更の履歴、履歴の時点へ戻す（戻すのも一つの変更として残る）、相手のメール（連絡先の住所）で受信箱を引いた「関係するメール」（メールを読める人だけ） |
| CSV の取り込み | 見出しの名前から列を当てる（画面で変えられる）。取り込む前に、新規・更新・飛ばす行の下見を出す。同じ団体名と年度は更新。空欄は今の内容を消さない。行番号は CSV の実際の行 |
| 一斉送信 | 一覧で団体を選ぶ（最大 30 団体） → 件名と本文（差し込み）→ 下見（団体ごとの文面と送らない理由、以前の送信の警告）→ 共通の添付（任意）→ 確認（件数と送信元の受信箱）→ 送信。1 通ずつ別々の宛先へ送る |
| 送りかけの一斉送信 | 途中で止まった（上限・権限・画面を閉じた）一斉送信は、一覧の上に出て、続きから送れる |
| テンプレート | 件名と本文を保存して、一斉送信の画面で次から選んで使う（§9） |

差し込み（本文と件名に書く）：`{団体名}` `{担当者名}` `{年度}` `{種別}` `{金額}` `{協賛内容}` `{委員会の担当}` `{状態}` `{次の対応}` `{期限}`。
ほかの書き方（`{住所}` など）はテンプレートを保存するときに止めます。差し込みの値が空の団体は、下見で理由を出し、送りません。

## 2. 使い方

### 台帳

1. 連絡先タブの「団体」を押す。
2. 「団体を追加」で入れる。相手の担当者は、連絡先を名前・組織・アドレスで探して選ぶ（結ぶと、一斉送信の宛先はその連絡先のメールアドレスになる）。
3. 一覧の行を押すと詳細が出る。「編集する」で直す。状態は詳細の「状態を変える」で選ぶとすぐ保存される。

### CSV の取り込み（協賛マスターなど）

1. 「CSVから取り込む」→ CSV ファイルを選ぶ。Excel で「CSV（コンマ区切り）」として保存したものをそのまま使える（Shift_JIS でも UTF-8 でも読める）。
2. 年度、種別（種別の列がない行に使う）、列の対応を決める。団体名は必須。
3. 「下見を見る」で、行ごとの結果（新規・更新・飛ばす）と理由を確かめる。
4. 「この内容で取り込む」で書き込む。下見のあとに団体の内容が変わっていれば、書き込まず下見をやり直すよう出る。

取り込みの規則：同じ団体名（全角・半角と空白を無視して比べる）と同じ年度は更新。同じ取り込みの中で団体名が重なる行は飛ばす。相手のメールが連絡先になければ、結ばずに登録して下見に書く。委員の名前は、委員会の名簿の表示名と一字違わず一致する必要がある。種別を変える行では、今の状態がその種別で有効なら残す。

### 一斉送信

1. 一覧で団体の欄にチェックを入れる（「表示中の件数を選ぶ」もある）。一度に選べるのは 30 団体まで。年度を変えると選択は空になる。画面の下に「選んだ団体に一斉送信」が出る。
2. 送信元の受信箱を選ぶ（選べるのは、送信の権限を持つ受信箱だけ）。テンプレートを選ぶか、件名と本文を書く（書いた文面は、テンプレートを選ぶと確認のうえ置き換わる）。
3. 「下見を作る」：団体ごとの宛先・件名・本文が出る。送らない団体には理由が出る（宛先がない、差し込みが空、件名や本文が長すぎる、同じ件名を以前に送っている）。件名が違う以前の送信があるときは注意を出す。
4. 共通の添付（任意）：下見の画面で、ファイルを追加・外せる。1 通に付くのは合わせて 10 個・送信の設定の上限（`mailbox.json` の `send.maxAttachmentBytes`）まで。下見の間だけ変えられる。
5. 「○件を送る」：確認の文と送信元のアドレスを確かめてから押す。進み具合が出る（一回の要求で 5 通ずつ進める）。
6. 結果：送った団体名、送った数、送れなかった数、届いたか分からない数。「送れなかった N 件を再送する」は、送れなかった宛先を一巡して送り直す（各宛先は一度の再送で一度だけ試す）。届いたか分からない宛先は再送しない。
7. 途中で画面を閉じたときは、一覧の「送りかけの一斉送信」から「続きを見る」で、残りを送れる。

送った内容は、送った団体の履歴に「一斉送信」として残ります（件名と通数）。メールそのものは、メールの画面の送信済みに「完了」として残ります。

## 3. 送信の守り

- 1 回の一斉送信は最大 30 団体（`ORG_LIMITS.batch`）。30 団体を超える要求は、何団体かを示して止める（422）。送信の上限（1 人 1 時間 30 通、`mail/send.ts` の `SENDS_PER_HOUR`）と同じ。上限に当たったら、その時点で止め、残りは「続きを送る」で後から送れる（時間をおく）。
- 送る文面は下見の時点で作って保存する。送るときは、保存された件名と本文をそのまま使う（下見のあとで団体の内容を直しても、送るのは下見の文面）。内容を直したら下見を作り直す。
- 宛先ごとに、送信用の識別子（トークン）を 1 つずつ持つ。送信は既存の送信の仕組みを使うので、同じトークンで二重には送らない。
- 同じ件名（差し込み後）を、その団体へ以前に送っている場合は、既定で送らない（理由を出す）。件名を変えれば送れる。件名が違う以前の送信は、下見で警告だけを出す。
- 送る直前にも、宛先ごとに確かめ直す（2026-11-04）。別の一斉送信が同じ団体へ同じ件名を送った・送っている・届いたか分からない（送信済み・送信中・不明）ときは、その宛先を送らずに「送らない」にして理由を残す。同じ件名の下見を 2 つ作ってから両方で送っても、届くのは先に送ったほうの 1 通だけ。団体の履歴の記録に失敗していても、一斉送信の記録で止める。
- 下見の注記：同じ団体・同じ件名の送信待ち（送っていない・再送待ち）が別の一斉送信にあるときも、「先に送ったほうだけが届き、あとから送るほうは止める」と出す。
- 送信の途中で止まった宛先（届いたか分からない）は、再送しない。10 分たっても「送信中」のまま残った宛先は、次の送信の要求で未確認になる。
- 送信済みの記録を団体の履歴に書けなくても、宛先は「送った」のまま残す（記録の失敗で送信済みを未確認にしない）。
- 添付は、下見（送信前）の間だけ追加・削除できる。送信が始まると変えられない。送る宛先すべてに同じ添付を付ける。
- 一斉送信は、作った本人だけが見ることも送ることもできる。送る権限を取り消されたあとは、その時点で止まり、残りは送らない。

## 4. データの置き場所

- `SMM_MAIL_DIR`（メールの保存フォルダ）の `organizations.sqlite3`。連絡先の `contacts.sqlite3` の隣に置く。
- 独自のスキーマ版（`meta.schema = 1`）を持つので、連絡先のファイルとは互いに影響しない。
- テーブル：`organizations`（団体）、`organization_history`（履歴。変更の前の内容を `before_json` に残す。一斉送信は `mail_sent` の行）、`mail_templates`（テンプレート）、`mail_batches` と `mail_batch_items`（一斉送信。文面と宛先と送信の状態）、`mail_batch_attachments`（一斉送信の共通の添付。ファイルの中身を BLOB で持つ）。
- 統合アプリの日々のバックアップ（`ops/backup.ts`）に含める。整合性の確認と件数を `manifest.json` に記録する。

## 5. 権限

サーバーで毎回確かめます（画面で隠すだけにはしていません）。

| 操作 | 必要な権限 |
|---|---|
| 台帳の閲覧、追加、編集、履歴から戻す、状態の変更、CSV の取り込み、テンプレートの閲覧・作成・編集 | 委員（臨時スタッフは不可。連絡先と同じ規則） |
| 団体の削除、テンプレートの削除 | 権限の管理者 |
| 相手のメールの一覧（「関係するメール」） | メールを読む権限（メールの画面と同じ。メールの画面の再入力の時間と試行利用者の規則も通る） |
| 一斉送信の下見・添付・確認・送信 | 委員、メールの画面と同じ入口の確認（放置後の再入力、試行利用者）、送信元の受信箱の送信の権限 |

送信の画面は、送れる受信箱が無い人、またはメールを読めない人には出しません（`GET /api/organizations/meta` が `mail.enabled` と `mail.readable` と `mail.from` を返す。送信の記録先のアドレスは返さない）。
メールの権限を確かめるときは、利用時刻を記録しない（`mailPeek`）。一覧を開くだけでメールの再入力の時間が延びることはない。

## 6. 有効にする方法

- `SMM_AUTH_MODE=discord` で動かし、委員会の受信箱（`SMM_MAIL_DIR`・`SMM_MAIL_CONFIG`）を設定すると、連絡先と同じように団体も使えます。
- 一斉送信は、メールの送信の設定（`mailbox.json` の `send`）がある場合だけ。無いときは台帳だけ使え、送信の入口は出ません。
- 送信の設定と権限の付け方は [docs/mail.md](../../docs/mail.md) §3 を見てください。

## 7. 設計の判断

- 新しい SQLite を 1 つ足した（連絡先の表に足すと、連絡先のファイルのスキーマ版を変えることになり、古い版との互換が崩れるため）。団体の中の「相手の担当者」は連絡先の ID で結び、アドレスは送るときに連絡先から読む。
- 送信は 1 要求あたり 5 通ずつ。1 要求で 30 通の SMTP を順に送ると、プロキシの時間切れにかかりうるため。画面が進み具合を表示する。
- 再送は、要求ごとに「どこまで試したか」（afterIndex）を送って前へ進む。失敗が続く宛先が先頭に並んでも、後ろの宛先まで届く。版の列を増やさないための形。
- 添付は、下見の作成（JSON）とは別の口（multipart）で足す。下見の文面は変えずに、添付だけを下見の間に変えられるようにするため。
- 取り込みの確定は、下見の結果の要約（planToken）と今の台帳から作り直した結果が一致するときだけ書く。
- 行番号は CSV の物理行（改行を含む引用セルや空行を数える）。
- 「関係するメール」は、メールの画面に検索の引き渡しが無いため、サーバーでメールの一覧の関数を呼ぶ形にした（送信・閲覧の関門はメールと同じ）。
- 連絡先タブの「団体」の表示区分だけを URL（`#/contacts?section=organizations`）に残す。一覧の絞り込みは画面の中だけ（§9）。

## 9. 残り（未実装・未確認）

- テンプレートは一斉送信の画面だけで使える（保存・選択）。メールの作成画面（返信など）からは使えない。共有のメールの画面に手を入れないため見送った。テンプレートの編集と削除は API（`PUT`・`DELETE /api/organizations/templates/:id`）だけで、画面にない。
- 出展団体の画像データ（ブースの図・ロゴなど）の管理は扱っていない。数字で管理する代わりに、ファイルを団体に紐づける仕組みは未実装。
- 添付は一斉送信の全宛先に同じものだけ。宛先ごとの添付は未実装。
- 状態の入力（協賛と出展団体以外の種別）は自由な文字。表記ゆれ（「入金済」と「入金済み」）の候補（datalist）と、チップの件数の絞り（上位だけ表示）は未実装。
- 一覧の絞り込み（年度・種別・担当・部局・状態・検索）は画面の中だけで、URL には残らない。団体の画面から戻ったときは、表示区分（団体）だけ戻る。
- デモモード（`SMM_AUTH_MODE=demo`）では、合成データの連絡先・団体・会計を出す（2026-11-03 の入金確認から。合成データは `server/payments/demo.ts` が作る。[payments.md](payments.md) §5）。デモでは一斉送信とメールは使えない（入口も出ない）。2026-11-03 までは、デモでは連絡先と同じく団体も出ず、`server/organizations/seed.ts` の初期値もデモの画面に接続していなかった。
- 団体の履歴の入金の行（入金を確認・入金の確定を外す・請求の変更を反映）の金額・入金日・請求番号は、会計を見る権限がある人にだけ返す（ほかの委員には、状態を動かした行だけを出す。[payments.md](payments.md) §4）。
- 画面の動作は実機（ブラウザ）で確かめていない。E2E の試験（`tests/e2e/`）は書いていない。スマホ幅（375px・320px）の表示は CSS の読みによる判断（団体の一覧と詳細は 900px 以下で 1 列に切り替える）。
- 団体の CSV 書き出しは未実装。
- 1 時間 30 通の上限は、メールの送信全体で共有する（一斉送信だけの上限ではない）。
- 送りかけの一斉送信の一覧は、送信の途中で止まったもの（上限・権限）と、失敗が残っているものを出す。取り消しや「送らない」の決定はできない。

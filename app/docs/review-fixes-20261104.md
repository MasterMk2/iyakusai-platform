# 第1波の統合版の検証で出た指摘の直し（2026-11-04）

第1波の 8 機能（決定事項・人ごとの持ちタスク・締切カレンダー・メールの回答期限・団体の台帳と一斉送信・物品の付属品と数の物品と回収表・Bot の週1回の一覧と通知の送り先・Bot の権限と監査）を統合した版を検証して出た指摘のうち、直したものと直さなかったものをまとめます。各機能の説明は、それぞれの文書（[decisions.md](decisions.md)・[calendar.md](calendar.md)・[organizations.md](organizations.md)・[supplies.md](supplies.md)・[mail-deadlines.md](mail-deadlines.md)・[task-people.md](task-people.md)・[bot/docs](../../bot/docs/)）にも反映しました。

## 何が変わったか

### 土台

- `main`（タスクの再開を、編集できる人なら誰でもできるようにする #7）を取り込みました。統合版はこの変更より前の `main` から作られていたため、そのまま組み立てると、タスク API の再開が役員だけに戻り、画面と API の判断も食い違っていました。取り込みに衝突はありません。検証はすべて取り込んだあとの木で行いました。

### 止まる・二重になる不具合

- **臨時スタッフが数の物品・回収表を使えなかった**：Discord ログインの臨時スタッフは、呼べる API を許可の一覧で絞っています。この一覧に `/api/rental/supplies` 以下の経路が一つも無く、読み込みも貸出・返却もすべて 403 でした。`rental.loan` で足りる経路（見る・貸す・返す・使う・付属品の点検・貸出と返却の取り消し）を足しました。品目・在庫・付属品の定義（`rental.issue`）は足していません。
- **団体への一斉送信で、同じ件名が二重に届くことがあった**：同じ件名の確かめが下見のときだけだったため、下見を 2 つ作ってから両方で送ると、両方とも届きました。送る直前に宛先ごとに確かめ直し、別の一斉送信が同じ件名を送った・送っている・届いたか分からないときは送らずに理由を残します。下見の注記も、別の一斉送信に同じ件名の送信待ちがあるときに出します。
- **`decisions.sqlite3` を開けないとアプリ全体が起動しなかった**：ほかの台帳（カレンダー・団体・連絡先・議事録）と同じく、決定事項だけを止めるようにしました。起動のログに「決定事項だけを止めました」と出ます。画面の入口は出ず、Bot の口は `decisions: null` を返します。
- **受信箱の無い Discord ログインで、カレンダーが別のファイルに書かれた**：受信箱（`SMM_MAIL_DIR`）を設定しない Discord ログインでは、カレンダーを使わない（503）ようにしました。決定事項と同じ扱いです。

### 画面

- **メールの期限の色・枠が PC で効いていなかった**：決定事項の CSS の `@media (max-width: 680px)` の閉じ括弧が無く、後ろのメールの期限の CSS がすべてその中に入っていました。閉じ括弧を足しました（`styles.css` 全体の括弧の深さが 0 になることと、ビルドした CSS で `.due-panel` がメディアクエリの外にあることを確かめました）。
- **ホームの上の「対応が必要な件数」**：「返事待ちで期限を過ぎたメール」と「今日・明日の予定と期限」を足しました。押すとそれぞれのカードへ移ります。今日が期限の自分のタスクは、すでにある「今日が期限のタスク」に数えるので、重ねて数えません。何も無いときの文も、新しい項目を含めた言い方にしました。数は各カードが取った結果を使うので、要求は増えていません。
- **ホームの並び**：「近づいている予定と期限」を「タスクの残数」の上（メールの期限のすぐ下）へ移しました。
- **メールの期限のカード**：委員会の受信箱でない構成（`/api/mail/due` が無い）では、エラーを出さずにカードごと出しません（カレンダーのカードと同じ）。
- **物品の画面の Service Worker**：キャッシュの名前を `iyakusai-rental-shell-20261104-v22-supplies` にしました。入れ替えると、端末の古い `styles.css` が新しくなります。
- **タスクの表示の切替**：どの表示でも同じ位置（検索と絞り込みの上）に出るようにしました。幅 360px 以下では、ラベルを一語のまま折り返さず、ボタンごとに 2 段に並べます。
- **ホームの「最近の決定・変更」**：状態の札が帯にならず、件名・状態・日時が一行に並ぶようにしました。
- **カレンダー**：予定の項目の中身を左にそろえました。「月の表／毎年の予定」の切替を、タスクの表示の切替と同じ見た目（選んだほうだけ塗る）にしました。
- **団体と連絡先**：団体の詳細の「相手の担当者」を押すと、その連絡先が開きます。開いている団体は URL（`#/contacts?section=organizations&org=…`）に残るので、関係するメールへ移ってからブラウザで戻ると、同じ団体が開きます。
- **言葉の統一**：人ごとの表示の「担当なし」を「未割当」に、Bot の週1回の一覧の「期限切れ」を「期限超過」に（どちらもタスクの画面と /todo の言い方）。タスクの日付は「期限」、カレンダーの予定の種類だけを「締切」とし、ホームのカードは「近づいている予定と期限」にしました。メールの一覧の並べ方の欄は「並べ順」にしました。

### Bot

- `/roles` に権限の判定と監査を付けました（種類は「読む」）。登録するスラッシュコマンドすべてに判定が付いていることを確かめる試験を足しました（`/help` と `/todo help` は対象外）。
- 決定事項の読み方（`decisions_logic.py`）の説明と、決定事項・契約・週1回の一覧の文書の「まだ無い」「別の変更で作る」を、統合後の事実に直しました。

## 使い方

使い方は変わりません。臨時スタッフは、物品の画面の「数の物品・団体の回収」から、委員と同じように貸出・返却・点検を記録できます（品目の追加や在庫の補正の入口は、もともと `rental.issue` の人にしか出ません）。

## データの置き場所

新しい保存先はありません。本番（Discord ログイン）では、受信箱の保存先（`SMM_MAIL_DIR`）に次の SQLite のファイルが並びます。どれも `ops/backup.ts` が `mailbox/` の下へオンラインバックアップで複製し、件数を `manifest.json` に記録します。

| ファイル | 中身 |
|---|---|
| `mail.sqlite3` | メール（回答期限・返事待ちと、その履歴を含む） |
| `contacts.sqlite3` | 連絡先 |
| `decisions.sqlite3` | 決定事項と履歴 |
| `organizations.sqlite3` | 団体の台帳・履歴・一斉送信 |
| `calendar.sqlite3` | 予定・履歴・取り込み URL のハッシュ |
| `minutes.sqlite3` | 議事録（`minutes.json` があるとき） |

**運用の手順書（`docs/deployment.md`）はこの作業では変えていません**（変更の対象外のファイル）。§3 の `SMM_MAIL_DIR` の行と §5 の複製の一覧に上の表の内容を、§3 の環境変数の表に `SMM_CALENDAR_ICAL`（未設定のとき Discord ログインでは off。`on`・`off` 以外は起動しない。[calendar.md](calendar.md)）を、§7 に下の「切り戻しの注意」を足す必要があります。主担当が反映してください。

## 権限

- 臨時スタッフ：数の物品・付属品・回収表の、見る・貸す・返す・使う・点検と、貸出・返却・使ったの取り消し。経路の許可（`discord-auth/temporary-staff.ts`）と、物品の権限（`rental.loan`）の両方をサーバーで確かめます。在庫の補正の取り消しは `rental.issue` が無いので 403 です。
- 一斉送信の送る直前の確かめは、権限に関係なく全員に効きます。
- Bot の `/roles` は「読む」の種類です。`[permissions.roles]` の `read` で絞れます。

## 有効にする方法

新しい設定はありません。この版を入れ替えると有効になります。

## 切り戻しの注意

- **Bot の `kiban.sources` の `"decisions"`**：統合アプリを決定事項に対応する前の版へ戻すときは、先に Bot の `[kiban]` の `sources` から `"decisions"` を外して Bot を再起動します。旧版の統合アプリは知らない `sources` を 401 で断るので、外さずに戻すと、物品・受信箱の写し（`kiban/rental.md`・`kiban/mailbox.md`）まで更新が止まります。
- **メールの履歴の種類**：新しい版で回答期限・対応期限を付けると、`mail.sqlite3` の履歴に `due`・`reply_wait` の行が入ります。旧版へ戻すと、メールの詳細の履歴にこの行が種類の名前なしで出ます（「名前: 「なし」→「11月10日（火）」」のように、何の変更か分かりません）。表を足しただけなので、旧版でもファイルは開けます。
- **決定事項のファイル**：開けないときは決定事項だけが止まり、ファイルは変更しません。退避するか、バックアップから戻して再起動します。今後スキーマの版を上げた版から戻したときも、同じく決定事項だけが止まります。
- **Bot の権限の表**：`/roles` を表（`access.py` の `COMMAND_KINDS`）に足しました。表を使わない既定の設定では今と同じく全員が使えます。

## 直さなかったもの

- **本番にしか無い Bot の命令名**：本番の Bot は見られないため（SSH を使わない）、手元にある `task_cog.py` の写し（10/31 の本番の写しを含む）すべての `/todo` の命令名を集めて表と比べました。すべて表にありました。本番の今の版は未確認です。今後は、登録するコマンドに判定が無いと試験が落ちます。
- **決定事項の部局が `planning` などのキーのまま出る（デモ・タスク機能が無いとき）**：部局の名前はタスク機能から引いています。統合アプリに名前の表を別に持つと、タスク機能の名前とずれるおそれがあるため、直していません。タスク機能とつないだ本番では名前で出ます。
- **連絡先の詳細に「この連絡先の団体」を出すこと**、**団体の一覧の絞り込みを URL に残すこと**：API を足す必要があるため、今回は団体から連絡先へのリンクと、開いている団体の URL だけにしました。
- **`docs/deployment.md` の更新**：変更の対象外のファイルのため、内容はこの文書の「データの置き場所」と「切り戻しの注意」に書きました。

## 残り

- 画面の確認は、デモ（合成データ）で幅 1280px・375px・320px を描画した範囲です（ホームとタスク。団体の画面は描画していません）。実機（スマホ）と本番の構成は未確認です。Playwright の E2E は回していません（spec は変えていません）。変えた言葉（未割当・期限・並べ順・カードの題・何も無いときの文）と、動かした要素（表示の切替・`.task-list-summary`・ホームのカードの並び）を spec で探し、古い言い方や、カレンダーの表示で `.task-list-summary` を見る箇所が無いことは確かめました（`app.spec.ts` の「担当なし」はメールの担当の選択肢で、今回は変えていません）。表示の切替の位置を変えたので、タスク画面の E2E（`ux-layout`・`ux-redesign`）は統合のときに回してください。
- 受信箱の無い Discord ログインでは、タスク画面の「カレンダー」の表示を押すと「カレンダーの保存ファイルを開けませんでした」と出ます（503）。入口を隠すには、カレンダーが使えるかを画面に知らせる口が要ります。

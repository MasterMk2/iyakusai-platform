# 要件

この文書では次の区分を使う。

- **必須要件**：利用者から依頼された内容。
- **採用した既定（試験版）**：依頼で提案された既定を検討し、ローカル試験版で採用したもの。本番で見直してよい。
- **実装済みの動作**：現在のコードとテストで確認している振る舞い。
- **提案**：今後の候補。未実装。
- **本番前に決めること**：試験版では決めずに残した判断。

## 必須要件

- 委員会の Todo を作成し、一覧できる。
- 架空の委員から担当者を選んで割当・解除できる。
- 期限を設定・変更・解除できる。
- 状態を変更できる。
- 目的、成果物、完了条件、不明点を別々に編集できる。
- 変更履歴を表示できる。
- 閲覧者・編集者・管理者の基本的な権限がある。
- 模擬 Bot の入出力アダプターを、共通のドメイン操作から分離して用意する。
- 試験の提供面は Web UI。実際の Discord Bot には接続しない。
- 架空データだけを使い、認証情報なしで試せる。既存業務データ、実ユーザー、個人名、トークンを含めない。
- OAuth、認証情報、Bot 登録、他者招待、API 課金、アクセス権追加、本番運用は行わない。

## 採用した既定（試験版）

| 項目 | 採用した既定 |
| --- | --- |
| 担当者数 | 1 人まで。未割当も可。候補は同じ委員会の **有効な** 所属者（役割は問わない）。 |
| 担当と権限 | 担当者になっても権限は増えない。他委員会の閲覧・変更はできない。 |
| 状態 | 未着手（todo）・進行中（in_progress）・保留（blocked）・完了（done）。完了以外の間は自由に切り替えられる。完了からは明示的な「再開」操作で未着手に戻す。完了と再開は画面で確認する。 |
| 期限 | 任意の日付のみ（YYYY-MM-DD、2000〜2100 年の実在日）。表示は `YYYY/MM/DD（曜）`、未設定は「期限なし」。期限超過は日本時間（Asia/Tokyo）の今日より前で、完了していないもの。 |
| 要件の入力 | 作成時はタイトルだけ必須。目的・成果物・完了条件・不明点は任意で、空欄は「未入力」として一覧（件数）と詳細（項目ごと）に出す。完了条件が空でも完了は禁止せず、確認画面で警告する。 |
| 管理単位 | 委員会（ワークスペース）。架空の委員会を 2 つ用意し、相互に分離する。 |
| 役割 | 閲覧者：所属委員会のタスク一覧・詳細・履歴・メンバー一覧を読む。編集者：加えてタスクの作成と変更。管理者：加えて所属者の役割と有効・無効の変更、役割変更記録の閲覧。 |
| 所属の無効化 | 次の要求から拒否する。担当は自動で外さず「所属が無効」と表示する。新たな割当はできない。 |
| 管理者の自己変更 | 自分自身の役割・有効状態は変えられない（管理者不在を防ぐ）。 |
| 同時編集 | 変更には更新版（expectedVersion）を付け、古い版への変更は拒否して最新内容を返す。 |
| 再送 | 変更要求に操作 ID を付けられる。同じ人物・同じ入口の同じ ID は一度だけ適用し、再送には現在の内容を返す。内容の違う再利用は拒否する。模擬 Bot で別チャンネルから同じ ID を送った場合も別内容として拒否する。 |
| 保存 | ローカル JSON ファイルにまとめて保存（1 プロセス専用）。サンプルデータに戻す操作がある。 |
| 模擬ログイン | 架空の人物を画面で切り替えるだけ。本人確認はしないことを常に表示する。 |

## 実装済みの動作

1. タイトルだけで Todo を作成でき、未割当・未着手で保存される。空・空白のみ・121 文字以上・改行や制御文字を含むタイトルは保存されない。
2. 編集者は候補から担当者を選んで割当・解除できる。他委員会の人物、無効な所属者、存在しない人物は割り当てられない。
3. 期限・状態を変更すると一覧と詳細に反映される。不正な日付（例: 2026-02-30）は拒否する。完了から他の状態へは「再開」でだけ戻せる。
4. 目的・成果物・完了条件・不明点を個別に保存でき、空に戻すと再び「未入力」になる。
5. 閲覧権限のない利用者には一覧・詳細・履歴を返さない。直接 ID を指定しても同じ（所属外のタスクは「見つからない」と応答し、存在を明かさない）。
6. 成功した変更はタスクと履歴に同時に保存される。保存に失敗した変更はどちらにも残らず、同じ操作 ID で再試行できる。
7. 古い版への変更は拒否し、最新内容を示す。画面では入力中の内容を残す。
8. 一覧を状態・担当者（未割当を含む）・期限（期限超過・期限あり・期限なし）で絞り込める。該当なしを表示する。
9. 模擬 Bot のコマンド（作成・一覧・詳細・割当・状態・再開・期限・要件）は Web と同じ操作・権限・履歴を使う。チャンネルに対応する委員会のタスクだけを扱う。重複配信は一度だけ処理する。
10. 画面には読み込み中・空・入力エラー・保存失敗・再試行・競合・キャンセルの状態がある。キャンセルした編集・作成・確認画面は何も保存しない。
11. デモ操作で読み込み失敗・保存失敗・応答遅延を指定回数だけ起こせる。

確認方法は README の「開発用コマンド」と `tests/`・`e2e/` を参照。

## 本番前に決めること

| 項目 | 内容 |
| --- | --- |
| 認証 | 実際の本人確認（Discord OAuth など）。模擬ログインは本番で使えない。 |
| 保存 | 複数プロセス・複数人で使える DB、バックアップ、復旧。 |
| 履歴と退会 | 保存期間、退会者の表示名の扱い、操作 ID 記録の保持期間（試験版は最新 2000 件）。 |
| Bot 連携 | 登録対象、要求権限、チャンネルと委員会の対応の管理方法、外部 ID の対応表の管理。 |
| 運用 | ホスティング、監視、費用の上限、停止方法。 |
| 状態と完了条件 | 完了条件の未入力を警告に留めるか、完了を禁止するか。 |
| 期限 | 日付のみで足りるか、時刻やタイムゾーンを扱うか。 |

外部連携は、必要な登録、認証、権限、費用、運用対象を具体化してから明示的な承認を得る。

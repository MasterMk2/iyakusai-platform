# タスクの「人ごと」表示と「自分の持ち」

委員ごとに、いま誰がどのタスクを持っているかを見る表示です（2026-11-03）。担当なしのタスクに担当を付けることもできます。
ホームのタスクの残数のカードには、自分の持ちの要約を出します。

## できること

- **人ごと**（タスク画面の「一覧・人ごと」の切り替え）: 委員ごとに、主担当の数・副担当の数・進行中・保留・期限超過・7日以内が期限の数を出す。
  - 並べ順は「持ちが多い順」「持ちが少ない順」「名前順」。持ちは主担当と副担当の未完了の合計。
  - 名簿に載っている委員は、タスクが無くても 0 件で出る。
  - 名簿（委員の一覧）が届くまでは、人の一覧も「手が空いていそう」も出さない。読み込みの失敗は画面に出し、再試行できる。
  - 持ちの少ない委員には「手が空いていそう」を付ける（目安。断定ではない）。
  - 人の行を押すと、その人の未完了のタスクを主担当・副担当に分けて期限が近い順に出す。タスクを押すと、既存のタスク詳細が右に開く。
- **担当なし**（人ごとの上のボタン）: 担当の無い未完了のタスクを期限が近い順に出す。編集者と管理者は、担当者を選んで「担当を付ける」で主担当にできる。
- **自分の持ち**（ホームのタスクの残数のカード）: 主担当か副担当になっている未完了のタスクの数、期限超過、今日まで。「自分の担当を開く」で、タスク一覧を開き、担当を自分に絞り、部局はすべて選ぶ（ホームの数と同じ範囲。人ごとの表示では開かない）。

## 使い方

1. タスク画面を開き、表示の切り替えで「人ごと」を押す。
2. 上の「部局」の選択で、数える部局を絞れる（部局ごとの一覧と同じ規則）。
3. 人を押すと、その人のタスクが一覧に出る。「← 人の一覧に戻る」で戻る。
4. 担当なしを見るには、「担当なし N 件」を押す。担当者を選び、「担当を付ける」を押す。

## 数え方（変えるときはここを見る）

- 数えるのは**未完了**（未着手・進行中・保留）のタスクだけ。完了したタスクは、どの数にも入らない。
- 部局の絞り込みは、既存の一覧と同じ規則（部の選択は課を含む。複数の部局に付いたタスクは、どの部局を選んでも 1 件として数える）。
- 状態・検索・期限の絞り込みは、人ごとの数には使わない（人の全体の持ちを見るため）。
- 「7日以内」は、今日から 7 日後までに期限が来る未完了のタスク（期限超過は含めない）。既存の一覧の「7日以内」と同じ。
- 「手が空いていそう」は、部局のタグがある構成では**全部局**で、タグの無い構成ではこの委員会の中で、未完了の主担当が 1 件以下の、有効な編集者か管理者に出す（閲覧者と、所属が無効になった人には出さない）。目安の件数は `FREE_LEAD_LIMIT`（`app/src/client/components/tasks/people.ts`）。
- 自分の持ち（ホームの数）は、Bot ホストの集計（`/summary` の `mine`）か、デモの集計（`summarizeTaskGroups` の `me`）が数える。

## データの置き場所

新しい保存先は作っていない。タスクの正本は、従来どおりタスクの保存先（Bot ホストのタスク DB、またはデモの `SMM_TASK_DATA_FILE`）。
人ごとの数と一覧は、読み込んだタスクの一覧と名簿から、画面の中だけで計算する（ブラウザにも保存しない）。
「一覧・人ごと」の選択だけは、既存の表示の選択と同じくこのブラウザに残る。

## 権限

- 人ごとを見られるのは、タスク機能を使える委員（既存のタスク画面と同じ）。
- 担当を付けるのは、既存のタスクの更新と同じ規則。**サーバーが確かめる**: 担当の変更は `PATCH /api/tasks/:id` の既存の処理で、編集者以上の役割と、有効なメンバーであることを Task サービスが確かめる。閲覧者の画面には「担当を付ける」を出さないが、それは見せ方だけで、判定はサーバーにある。
- 担当に選べるのは、その委員会の有効なメンバー。版（`expectedVersion`）が古いと 409 になり、一覧を取り直す。

## 有効にする方法

- 人ごとは、タスク機能（`SMM_TASK_DATA_FILE` または `SMM_TASK_SERVICE_URL`）が動いていれば使える。設定は増やさない。
- 自分の持ちは、Bot ホストのタスク API（`bot/gateway/bot_task_gateway.py`）を、この変更の版に更新したときだけ出る。古い版の応答には `mine` が無いので、ホームのカードにはそのブロックを出さない（0 件とは書かない）。
- デモ（`SMM_AUTH_MODE=demo`）では、同じプロセスのタスク（`SMM_TASK_DATA_FILE`）で動く。部局ごと・関係図は、部局のタグを持つタスク API のときだけ出る（従来どおり）。

## 試したこと

- 単体試験（`tests/unit/task-people.test.ts`）: 数え方（完了の除外、主担当と副担当、期限超過、7日以内の境界）、名簿に無い人、無効になった人、「手が空いていそう」の条件、並べ順、担当なしの並び、一人分の内訳。
- 単体試験（`tests/unit/task-summary.test.ts`）: 自分の持ちの数え方（同じタスクを二つの部局で数えても 1 件、完了の除外）、呼び出し側が ID を渡さないときは項目ごと出さないこと。
- API の試験（`tests/api/tasks-people.test.ts`、デモのタスク）: 自分の持ちの数、担当なしのタスクへの担当の付与、閲覧者の 403、古い版の 409。
- Bot の試験（`bot/gateway/test_task_summary.py`）: `mine` の数え方、担当の無い呼び出しで項目を出さないこと。（Windows で動かすと、ファイル権限の試験が既存の失敗として 1 件残る。変更の前後で同じ。）
- 画面（デモ、Chromium、合成データ）: 375px と 320px で、人ごとの一覧・担当なしの担当付け・ホームの自分の持ちを描画し、横のはみ出しが無いことを確かめた（`scrollWidth` と `clientWidth` が同じ）。担当付けは保存され、「○○にしました」の表示が出た。

## 残り・未確認

- E2E（Playwright の `tests/e2e/`）の人ごと用の試験は追加していない（統合のときに主担当がまとめて回す）。
- 部局の絞り込みと人の関係（人は部局に属さない）: 部局で絞ると数えるタスクだけが変わり、人の一覧は変わらない。部局のタグがある構成では、他の部局で忙しい人が空いて見えないよう、「手が空いていそう」は全部局で判定している。タグの無い構成では、この委員会の中の担当だけを見る（他の委員会の担当は数えない）。
- 「手が空いていそう」は主担当の数だけで決めている（期限超過の有無は見ない）。期限超過があっても出ることがある。
- 本番の Bot ホストは、この変更の版への更新が必要（`mine` のため）。本番への反映はこの作業の範囲外。
- 320px・375px は確かめたが、タブレット幅や 200% 拡大は未確認。
- 2026-11-03 の検証の指摘の修正（名簿の読み込み中・失敗、部局が 0 件のときの案内、「自分の担当を開く」の初期表示と部局、担当付けのあとのフォーカス、タグの無い構成の注記）は、単体試験（週の境界、名簿が届く前の表示、初期表示の規則）だけで確かめた。修正後の画面の描画と、担当付けの再試行（同じ操作 ID）の画面の経路は未確認。
- 初期の部局（「自分の担当を開く」で部局をすべて選ぶ規則）は、画面の処理の中にあり単体試験の対象外。E2E も未実行。
- `tests/api/tasks-gateway.test.ts` の「task-only user ... mailbox」の失敗は、基準表の既存の失敗（36 件）の一つで、この機能とは関係がない。

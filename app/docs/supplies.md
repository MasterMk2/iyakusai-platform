# 数で管理する物品・付属品・団体ごとの回収

物品貸出（[物品管理の段階操作](unified/rental-workflow.md)）の横に置く、数で管理する物品と付属品の記録です。個体カードの貸出・返却の流れは変えていません。画面は `/rental/supplies`（物品貸出の画面の「数の物品・団体の回収」の入口から開く）。

## 何ができるか

1. **付属品**：個体（カード付き）と数の物品に、付属品の一覧（名前・1 個あたりの数）を持たせる。数の物品は、団体へ貸す・返す操作の中で付属品の在った数を一緒に記録する（借用時・返却時の点検）。足りない数は点検の記録に残り、「付属品の欠品」で分かる。個体カードの付属品は、回収表の「付属品を点検する」か個体コードの入力で記録する（随時・返却時）。
2. **数で管理する物品**：カードを付けない小物・机・椅子・延長コードは「貸し出す物品」、ペン・テープなどは「消耗品」として数で持つ。在庫数、団体に N 個貸す、団体から返してもらう（返った数と紛失・破損の数）、消耗品は「使った」で減らす。しきい値は品目ごとに決め、在庫がそれ以下のときは「残りわずか」、0 のときは「在庫切れ」と文字で出す（色だけでは示さない）。
3. **その場で貸す**：団体を選び、物品を押すと「何個入れるか」の欄が開く（数字を直接入力、または −1・＋1）。「今回に入れる」で今回貸すものに並び、付属品があれば在った数もその場で入れて、「○個貸す」で一度に記録する。
4. **団体ごとの回収**：団体に貸している個体・数の物品・付属品を一覧にする。未回収の団体を先に並べる。全部戻ると「回収済み」になる。返った数・欠品をその場で記録でき、A4 縦で印刷できる（ブラウザの印刷）。付属品の欠品は画面の下の折りたたみにまとめる。
5. **取り消し**：誤った記録は、取り消す記録を新しく足して戻す。元の記録は消さずに残る（履歴に「取り消し済み」と出る）。

## 使い方

- 物品貸出の画面の「数の物品・団体の回収」から開く。タブは「その場で貸す」「数の物品」「団体の回収」の 3 つ。
- 団体は、物品貸出の既存の貸出先（登録済みの団体）から選ぶ。登録されていない名前は、画面の「団体を登録する」で登録してから貸す（既存の貸出先の登録と同じ仕組み）。
- 付属品がある物品を貸す・返すときは、在った数（既定値は貸す数・返す数 × 1 個あたりの数）を入れてから記録する。在った数を入れないと記録されない。
- 紛失・破損の数は、返す数の既定値（返った数 × 1 個あたり）に含めない。紛失した分の付属品は既定で欠品として残る。
- 個体カード（IY- の番号）の貸出・返却は、従来どおり個体の画面で行う。その後、付属品の点検を「団体の回収」の回収表（その団体の個体の行）か、「個体の付属品を点検する」（個体コードを入力）で記録する。個体コードが登録されていないときは「この個体は登録されていません」と出る。
- 付属品の「しまう」は一覧から外すだけで、点検の記録は残る。「しまった付属品」の「戻す」で元に戻せる。

## データの置き場所

- 物品貸出の保存先（`SMM_RENTAL_DATA_DIR`）の `rental.sqlite3` に、次の表を**足して**作る。既存の表は変えない。
  - `supply_items`（品目の定義：名前・単位・種類・しきい値・メモ・版番号・アーカイブ）
  - `supply_movements`（数の動きの記録。追記のみ。在庫・貸出中・使った累計は、この記録の合計で求める）
  - `supply_attachments`（付属品の定義。個体の番号または品目の番号に付く）
  - `supply_attachment_checks`（点検の記録。欠品の数とメモを含む）
  - `supply_requests`（貸す・返す・使ったの操作の番号と、保存した結果。同じ番号の再送に答えるため）
- 物品の台帳のフォルダごと保存すれば、この表もバックアップに含まれる。
- Google ドライブへの複製（`drive-sync`）には**含めない**。既存のシートと出力の形を変えないため。
- 台帳の番号の初期化（No.100001 からの再登録）では、個体カードに付いた付属品と点検を、初期化の記録（`numbering_reset_archives`）に退避してから消す。同じ番号で再登録された個体に、旧い個体の付属品や点検は残らない。数の物品の付属品と記録は消さない。

## 権限

| 操作 | 必要な権限 |
|---|---|
| 見る（物品の数・団体の回収表・点検の記録） | `rental.loan` または `rental.issue` |
| 貸す・返す・使った・付属品の点検・貸出・返却の取り消し | `rental.loan` |
| 物品の追加・名前・しきい値・アーカイブ、在庫の補正、付属品の定義・しまう・戻す | `rental.issue` |
| 在庫の補正の取り消し | `rental.issue` |

権限はサーバーで確かめる（画面で隠すだけにしない）。権限のない人の入口は画面に出さない。臨時スタッフ（`rental.loan` のみ）は、貸す・返す・使う・点検まで。

## 有効にする方法

- 新しい設定はない。物品貸出が有効（`SMM_RENTAL_DATA_DIR` を設定）なら、同じ条件で使える。
- 試用（`SMM_AUTH_MODE=demo`）では、合成データ（「試用 パイプ椅子」「試用 養生テープ」など）が最初の起動で一度だけ入る。同じ保存先では増えない。デモのパイプ椅子は座面カバーが付いていて、初期データの団体への貸出は、座面カバーの点検を一緒に記録している。

## 同時編集と誤操作

- **版番号**：品目ごとの版（`expected_version`）。画面が読んだ版と違えば 409（`version_conflict`）。画面は最新の数を読み直し、「今回貸すもの」の数が在庫を超えたときは、超えた品目の数を在庫まで直して品目名を示す。
- **操作の番号**：貸す・返す・使ったには、画面が作る UUID（`id`）を付ける。同じ番号を同じ内容で再送すると、保存済みの結果を返し、二重には記録しない。同じ番号を別の内容で使うと 409（`request_conflict`）。通信が切れたときは、同じ内容のまま押し直すと安全（画面はそのように番号を保つ）。内容を変えたときは、先に団体の回収表で貸出数を確かめる。
- **在庫・貸出数はマイナスにならない**：在庫が足りないとき、団体の貸出数より多く返すときは拒否する（`stock_short` / `lent_short`）。どの品目かを名前で示す。
- **一度の操作はすべてか何もないか**：複数の品目を含む貸出・返却は、一つでも拒否されると全体を取り消す。付属品の点検も同じ操作の中で書く。点検が通らなければ、貸出・返却も記録されない。
- **付属品の点検は貸出・返却と一緒に**：付属品がある物品は、貸す・返すの行ごとに、付属品をすべて（一つも抜かさず）数える。数えずに送ると `attachments_required`。付属品の一覧が変わっていたら `attachments_changed`（画面は読み直す）。付属品がない物品に点検を送ると拒否する。
- **点検の番号（随時の点検）**：個体の随時の点検は、画面が作る番号（UUID）で記録する。同じ番号を再送すると、保存済みの点検を返し、二重には記録しない。
- **数の物品の単独の点検は随時だけ**：貸出時・返却時の点検は、貸す・返す操作の中で記録する（単独では送れない）。随時の点検の数は、在庫と貸出中を合わせた数以下。
- **団体の回収の欠品**：その団体の貸出のあとに記録された点検（その団体の点検と、団体名のない随時の点検）だけで数える。ほかの団体の点検は「前回の点検」として表示し、この団体の欠品にはしない。
- **団体の回収の「回収済み」**：その団体に貸している個体が 0 件、数の物品が 0 個のとき。付属品の欠品があっても回収済みとは別に「欠品 N 件」と出す。個体の状態は `loaned` と、古い台帳の `borrowed` のどちらも貸出中として数える。

## API（`/api/rental/supplies`）

| メソッド・パス | 用途 | 権限 |
|---|---|---|
| `GET /` | 品目の数（付属品を含む）・登録済みの団体・最近の団体 | 見る |
| `GET /movements?item_id=&limit=` | 数の記録（新しい順） | 見る |
| `GET /board?group=` | 団体の回収表（この団体の貸出のあとの点検で付属品の欠品を数える） | 見る |
| `GET /collection` | 団体の一覧（回収済みか） | 見る |
| `GET /shortages` | 最新の点検で欠品が残っている個体・品目 | 見る |
| `GET /attachments?owner_kind=&owner_key=` | 付属品と最新の点検、点検の履歴、しまった付属品。個体・品目が無いときは 404 | 見る |
| `POST /items` | 品目を追加 | `rental.issue` |
| `PATCH /items/:id` | 名前・単位・しきい値・メモ・アーカイブ（`expected_version` 必須） | `rental.issue` |
| `POST /items/:id/stock` | 在庫の補正（`delta`・`expected_version`） | `rental.issue` |
| `POST /lend` | 団体に貸す（複数品目を一度に。`id` 必須。付属品のある品目は `attachments` の在った数が必須） | `rental.loan` |
| `POST /return` | 団体から返してもらう（返った数・紛失・破損。`id` 必須。付属品のある品目は `attachments` が必須） | `rental.loan` |
| `POST /consume` | 消耗品を使った（`id` 必須） | `rental.loan` |
| `POST /movements/:id/reverse` | 記録を取り消す（`reason`・`expected_version` 必須） | 貸出・返却は `rental.loan`、在庫の補正は `rental.issue` |
| `POST /attachments` | 付属品を追加 | `rental.issue` |
| `PATCH /attachments/:id` | 付属品の名前・数・メモ・しまう（`archived: false` で戻す） | `rental.issue` |
| `POST /attachment-checks` | 随時の点検を記録（`id` は UUID v4。個体は貸出・返却の区分も可。数の物品は `phase: check` だけで、`units` は在庫と貸出中の合計以下） | `rental.loan` |

貸す・返すの応答は `{ group, lines, checks }`。`checks` は点検の記録（欠品の数を含む）。

画面は `GET /rental/supplies`（HTML）・`/rental/supplies.js`・`/rental/supplies.css`。物品貸出と同じ CSP で配る。

## 残り

- 数の物品の貸出・返却の点検は、通信が切れている間の保存（端末に保留して、つながったら送る仕組み）には入っていない。送れなかった操作は画面に残らない（番号は同じ内容で押し直せば二重にならない）。
- 個体カードの返却の登録は個体の画面で行う。回収表から個体の返却を登録する操作はない（台帳の正本の処理を変えないため）。個体の付属品の点検は、個体の画面で返したあとに回収表から記録する。
- Google ドライブへの複製はない（上の「データの置き場所」）。
- ホームの「対応が必要な数」には出していない（在庫切れ・残りわずかの件数など）。
- 連絡先タブの団体台帳とはつなげていない。団体名は文字列で持つ（既存の貸出先の名前と一致させる）。
- 印刷はブラウザの印刷（A4 縦・余白 12mm）。実際のプリンターでは未確認。
- 消耗品の補充は「在庫の補正」として記録する。購入・支出の管理はない。
- 名前で同じ品目・付属品は登録できない（名前で探すため）。
- 取り消し（`reverse`）は、同じ番号での再送の仕組みを持たない。二重に押さないよう、画面は送信中に押せなくしている。
- 実機（スマホの画面の大きさ・指の操作・印刷）は未確認。試験は合成データ。

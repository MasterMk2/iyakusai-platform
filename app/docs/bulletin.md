# 掲示板

委員会の中のお知らせを 1 か所に載せ、まだ読んでいないお知らせをホームに出すための機能です（2026-11-11）。
上のタブに「掲示板」が増えます（ホームの隣）。物品貸出の画面のタブにも同じ並びで入ります。

## できること

- **お知らせを書く**：件名（80 字まで）と本文（4,000 字まで・改行はそのまま・`https://` で始まる URL はリンクになる）。書けるのは委員全員。
- **表示対象**：「委員全員」か、部局を 1 つ以上選ぶ。部局は委員の所属（ログインのロールの部局名）から出る。
  - 部局を選んだお知らせは、**その部局の委員と、書いた人・権限の管理者にだけ**見える。ほかの委員には一覧にも出ず、URL を直接開いても「見つからない」と出る（`404`）。
  - 部と課の両方に所属している人（例：総務部・会計課）は、どちらを選んだお知らせも見える。
- **掲載期間**
  - **掲載期限**（この日まで・日本時間）。書くときは 2 週間後が入っていて、「1 週間」「2 週間」「1 か月」「期限なし」のボタンでも入れられる。期限の翌日 0:00（日本時間）に、掲示板の「掲載中」とホームから外れ、「終了」の一覧に残る。
  - **掲載開始日**（任意）。先の日にすると、その日の 0:00（日本時間）までは書いた人と権限の管理者にだけ「これから」の一覧に出る。開始日になると、対象の人に新着として出る。
- **重要**：付けると「掲載中」の一覧とホームの新着で先頭に出て、「重要」の印が付く。
- **新着とホーム**
  - 対象のお知らせのうち、まだ開いていないものが「新着」。ホームの上のほうに「掲示板の新着（N 件）」の欄が出て（重要が先・新しい順・5 件まで）、「対応が必要な件数」にも「掲示板の新着」が出る。新着が無いときは欄ごと出ない。
  - お知らせを開くと、その人の新着から外れる（人ごとに記録する）。掲示板の「すべて既読にする」でまとめて外せる。
  - 書いた本人には、自分のお知らせは新着にならない。
- **直す・取り下げる・戻す**：書いた人と権限の管理者ができる。
  - 直すときに「直したことを新着としてもう一度知らせる」を付けると、すでに読んだ人にも新着として出る（直した本人を除く）。付けなければ新着は変わらない。
  - 取り下げたお知らせは消えず、書いた人と権限の管理者にだけ「終了」の一覧に「取り下げ」として出る。「掲示板に戻す」で、元の掲載期間のまま戻る。確認のダイアログは出さない（戻せるため）。
  - お知らせを消す操作はない。
- **開いた人の数**：書いた人と権限の管理者には、「開いた人：対象 N 人のうち M 人」が出る（最後に知らせてからの数。名前は出さない）。

## 使えない人

臨時スタッフ（ログイン ID が臨時スタッフの範囲・ロールが「臨時スタッフ」・臨時スタッフのセッション）と、委員として登録されていないアカウントには出ません（読むことも断る。`403`）。決定事項の台帳と同じ範囲です。

## 画面

- **掲示板タブ**（`#/board`）：左に一覧（掲載中・これから・終了）、右に選んだお知らせかフォーム。スマホでは一覧とお知らせを交互に出す。
- お知らせ 1 件は `#/board?p=<ID>`、書く画面は `#/board?new=1`。
- **ホーム**：「掲示板の新着」の欄（新着があるときだけ）。

## API

すべて `/api/bulletin`。ログインが要る。掲示板が使えないサーバーでは `meta` だけが答える（`enabled: false`）。

| 経路 | 内容 |
|---|---|
| `GET /meta` | 使えるか、選べる部局、自分の部局、今日（日本時間） |
| `GET /?list=current\|scheduled\|ended&page=&pageSize=` | 一覧（見えるものだけ）と新着の数 |
| `GET /summary` | ホーム用：新着の数と先頭の 5 件 |
| `POST /` | 書く（`clientToken` で二重登録を防ぐ。同じトークンで同じ内容なら最初のお知らせを返す） |
| `GET /:id` | 1 件（見えない人には `404`） |
| `POST /:id/read`・`POST /read-all` | 既読にする |
| `PUT /:id` | 直す（`expectedVersion`・`announce`。版が違えば `409`） |
| `POST /:id/withdraw`・`POST /:id/restore` | 取り下げる・戻す |

## 保存

`bulletin.sqlite3`（委員会のメールの保存先 `SMM_MAIL_DIR` の中。デモではデモのデータの隣）。起動のときに作る。

- `posts`：お知らせ（状態・件名・本文・重要・対象の部局・開始日・期限・最後に知らせた時刻・版）
- `reads`：だれがいつ開いたか（お知らせ × 人）
- `post_history`：書いた・直した・取り下げた・戻したの記録と、その前の内容

バックアップ（`dist/server/ops/backup.js`）は `mailbox/bulletin.sqlite3` を写し、3 つの表の件数を `manifest.json` に書きます。
ファイルを開けないときは掲示板だけが止まり（タブを開くと「使えません」と出る）、ほかの機能は動きます。

## 決めていること・していないこと

- 部局の名前はロールの名前そのまま。ロールの名前を変えると、前の名前を対象にしたお知らせはその部局に見えなくなる（書いた人が直す画面で選び直す）。
- 添付ファイル・コメント・Discord への通知は無い。
- 年度の切り替え（[rollover.md](rollover.md)）では写さない。
- 前の版のアプリに戻しても、`bulletin.sqlite3` は読まれないだけで残る。
